# Предыдущие версии SMB в Caja

Расширение добавляет пункт **Предыдущие версии…** к одному файлу, каталогу
или фону открытого SMB-каталога. Оно показывает даты доступных снимков.
Можно открыть версию файла или каталога. Для файла можно создать рядом
копию с датой в имени. Существующий файл с таким именем сохраняется.
Копия создаётся как обычный файл в текущем каталоге и получает его
правила наследования. Исторический Windows ACL отдельно не переносится.
Чтобы вернуть удалённый файл, откройте предыдущую версию ближайшего
существующего родительского каталога и скопируйте файл оттуда.

## Установка RPM на ALT p10

Из каталога, в котором лежит RPM, выполните с правами администратора:

```sh
apt-get install ./caja-smb-previous-versions-0.1.1-alt1.noarch.rpm
```

APT подберёт Caja, загрузчик расширений, PyGObject, GVfs SMB и smbclient
из подключённых репозиториев p10. Расширение устанавливается для всех
пользователей. После завершения активных файловых операций перезапустите
Caja в пользовательском сеансе. При обновлении с ручной установки уберите
прежнюю пользовательскую копию из каталога расширений, чтобы Caja не
загружала её одновременно с пакетной.

## Ручная установка для пилота

Нужны Caja с загрузчиком расширений python-caja, Python 3, PyGObject,
GTK 3, GVfs с SMB и smbclient с поддержкой `--use-kerberos=required`.
В репозиториях ALT p10 и p11 проверены пакеты `python3-module-caja`,
`samba-client` и `gvfs-backends`. Установите файл под учётной записью
пользователя Caja:

```sh
install -Dm644 sambaadm_previous_versions.py \
  "${XDG_DATA_HOME:-$HOME/.local/share}/caja-python/extensions/sambaadm_previous_versions.py"
```

Перезапустите Caja после завершения активных файловых операций. Откройте
ресурс по адресу `smb://имя-сервера.домен/ресурс` с работающим CIFS SPN.
Для запроса списка smbclient использует билет Kerberos из текущей сессии.
Открытие и копирование выполняются через GVfs от имени пользователя.
В пилоте используйте одну и ту же доменную учётную запись для GVfs и
Kerberos; при необходимости проверьте билет командой `klist`.
Поддерживаются подключения `smb://` по имени сервера без учётных данных
в URI. Для уже смонтированных локальных путей (`file://`) меню отсутствует.

## Автоматический выбор источника: Windows, ZFS, LVM

Расширение автоматически запрашивает общий механизм SMB Previous Versions
через `smbclient allinfo` (FSCTL_SRV_ENUMERATE_SNAPSHOTS). Windows VSS,
Samba с ZFS и Samba с LVM используют одинаковые метки `@GMT-…`.
Переключатель типа сервера и отдельные клиентские команды ZFS/LVM не нужны.
Открытие и копирование используют один и тот же исторический SMB-путь.
В диалоге указан общий протокол, а не предположительный тип дисковой системы.

SMB не раскрывает реализацию снимков: отличить ZFS от LVM или уверенно
определить Windows по списку версий невозможно. Даже имя файловой системы,
объявленное сервером, может быть настроено администратором. Расширение
определяет доступность истории по ответу сервера, а не по имени хоста.
Отдельно показываются неподдерживаемая операция, отказ в перечислении и
ошибка соединения. Пустой ответ не считается доказательством поддержки:
`smbclient` может молча пропустить перечисление при невозможности открыть объект.

На Windows Server включите Shadow Copies для тома с общей папкой и создайте
снимок. Доступ к истории должен работать под той же доменной учётной записью.
Для Samba снимки ZFS/LVM должны быть опубликованы сервером через
`shadow_copy2` или совместимый модуль. Одного наличия снимка на сервере
недостаточно. LVM-снимки требуется смонтировать и настроить `shadow:snapdir`,
формат имён и сопоставление путей; расширение не создаёт и не монтирует их.
Другие серверы/NAS поддерживаются, если предоставляют тот же SMB-механизм.

## Samba и ZFS

Проверьте первую конфигурацию на выделенной шаре в корне отдельного
dataset. Ниже пример для нового тестового ресурса. Замените путь, имя
dataset и перечень допущенных пользователей на значения стенда.

```ini
[shadow-pilot]
    path = /srv/smb/shadow-pilot
    read only = no
    valid users = @EXAMPLE\shadow-pilot
    vfs objects = acl_xattr shadow_copy2 streams_xattr
    acl_xattr:ignore system acls = yes
    shadow:snapdir = .zfs/snapshot
    shadow:format = shadow-%Y.%m.%d-%H.%M.%S
    shadow:localtime = no
    shadow:sort = desc
```

Этот пример использует Windows ACL для доступа через SMB. Для каталога
с доступом через NFS или локальным пользовательским доступом отдельно
спроектируйте POSIX ACL. При добавлении shadow_copy2 к существующей шаре
сохраните действующий список VFS-модулей. При раздаче подкаталога dataset
проверьте сопоставление относительных путей до и после снимка.

На сервере сначала проверьте `testparm -s`, точку монтирования и имя
dataset. Создайте в шаре тестовый файл, затем сделайте снимок:

```sh
zfs get mountpoint,snapdir tank/shadow-pilot
zfs snapshot "tank/shadow-pilot@shadow-$(date -u +%Y.%m.%d-%H.%M.%S)"
zfs list -t snapshot -r tank/shadow-pilot
```

Измените тестовый файл через SMB. Проверьте предыдущую версию. Для уже
имеющегося расписания из переписки `zfs-auto-snap_hourly-%Y-%m-%d-%H%M`
сопоставьте `shadow:format` с реальными именами и отдельно проверьте,
UTC это или локальное время. Для включения снимков разных периодов
используйте согласованные имена и правила удержания. Свойство
`com.sun:auto-snapshot` само по себе расписание не запускает.
Оставьте обычным пользователям доступ к истории через разрешённый SMB
ресурс с проверкой ACL. Снимки могут содержать исторические записи о правах,
поэтому в пилоте отдельно проверьте пользователя с отозванным доступом.

## Проверка

1. Сначала проверьте сервер с авторизованной рабочей станции:
   `smbclient //fs.example.test/shadow-pilot --use-kerberos=required -c 'allinfo "test.txt"'`.
   В успешном ответе после информации о текущем файле есть строки
   `@GMT-…` и метаданные соответствующей версии. Ряд версий smbclient
   не показывает подробности отказа при перечислении снимков.
2. В Windows проверьте вкладку «Предыдущие версии», чтение изменённого
   файла и чтение удалённого файла из снимка родительского каталога.
3. В Caja повторите те же операции, проверьте копирование рядом и
   ожидаемый отказ при совпадении имён. Отдельно проверьте, что чужая
   PERSONAL недоступна через живой и исторический пути.
4. Если список приходит по smbclient, а открыть снимок в Caja нельзя,
   проверьте отдельно открытие URI
   `smb://fs.example.test/shadow-pilot/@GMT-YYYY.MM.DD-HH.MM.SS/test.txt`
   на конкретной версии GVfs. Результаты на Windows и в Caja фиксируются
   отдельно.
