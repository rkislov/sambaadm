# Автономное обследование домена

Выполните сбор локально на каждом согласованном Linux-узле с установленным helper. Для этого режима достаточно конфигурации с именем узла. Сервис HTTPS, SSH-доступ к узлу и пароль домена для запуска сбора не требуются. Площадку указывает оператор.

```sh
sudo sambaadm-helper collect --config /etc/sambaadm-helper/config.yaml \
  --site Region-01 --out /var/tmp/dc1-survey.json
```

Укажите новый путь. Helper создаёт файл с правами 0600. В снимке сохраняются имя узла, версия helper, начало и завершение сбора, источник, время и результат каждой локальной проверки. Собираются версия ОС, ядра и пакетов, выбранные параметры Samba, состояния служб, DNS-настройки резолвера, источники и смещение времени по данным chrony. Статус observed означает, что команда вернула данные. Состояние синхронизации и величину отклонения оценивают по содержимому. Для отсутствующих инструментов сохраняется unknown.

Если задан helper.auth_log, helper читает до 8 МиБ конца файла и сохраняет до 500 событий Samba Authentication с выбранными полями. Имена пользователей, рабочие станции, адреса, DN и время входа могут относиться к внутренним сведениям. Проверьте состав материалов и используйте согласованный канал передачи.

## Импорт

1. Войдите в sambaadm с ролью администратора. На главной странице откройте «Материалы автономного обследования» или перейдите к /surveys.
2. Выберите формат и файл размером до 16 МиБ. Для снимка helper узел и площадка берутся из самого файла. Для отдельного журнала укажите контроллер-источник и при необходимости площадку.
3. Нажмите «Импортировать». Материал появится в списке с временем импорта. В карточке доступны SHA-256 входного файла, наблюдения с их собственным временем и события авторизации.
4. Добавьте файлы других узлов. Для данных доменного уровня используйте JSON из кнопки «Скачать отчёт обследования JSON» в обзоре домена sambaadm. Он переносит уже собранные разделы топологии, репликации и диагностики. Количество разделов зависит от проверок, выполненных до экспорта.

Отдельный журнал принимается в формате Samba JSON audit, одно событие на строку, с допустимым текстовым префиксом. Сохраняются нормализованные поля Authentication, число ошибочных строк и признак ограничения выборки. Для отдельного журнала нужен хотя бы один распознанный вход. Пустой журнал в снимке helper отображается вместе со статусом источника. Для обзора домена сохраняется содержимое JSON-выгрузки. SHA-256 позволяет сверить исходный файл, а происхождение файла подтверждает передавшая его сторона.

## Хранение и границы первого этапа

Параметр server.survey_dir задаёт закрытый каталог sambaadm. По умолчанию используется /var/lib/sambaadm/surveys с правами 0700. Службе требуется право записи. Лимит — 128 материалов. Повторный импорт того же содержимого с теми же метками возвращает сохранённый материал. Срок хранения согласует администратор. После передачи архива администратор может удалить соответствующий файл ID.json из этого каталога.

В v0.36.0 доступны карточки материалов и сводный отчёт по выбранным узлам. Фактический выбор DC рабочей станцией и результат испытания до и после изменения требуют отдельных наблюдений со стороны клиента.

## Сводный отчёт

В разделе «Сводный отчёт по ТЗ» выберите материалы одного домена за согласованный период и нажмите «Сформировать отчёт». Наблюдения сгруппированы по площадке и узлу. Идентификатор в строке соответствует сохранённому материалу. Для сравнения версий ОС, Samba и chrony используется последний по времени завершения выбранный снимок каждой пары «площадка, узел». Расхождение версий требует оценки с учётом роли узла. Разделы обзора и журналы показывают доступность материалов. Охват площадок, успешность репликации и выводы о состоянии домена администратор подтверждает отдельно.

### Охват контроллеров по площадкам

Выберите JSON обзора с разделом «Контроллеры из LDAP», снимки helper и журналы за нужный период. В начале отчёта появится строка для каждого DC с площадкой и ролью из LDAP, временем последнего снимка, состоянием источников авторизации и перечнем того, что запросить. Опорный перечень берётся из самого свежего выбранного раздела контроллеров по времени наблюдения. Если этот раздел недоступен или пуст, запросите новый обзор.

FQDN сопоставляются без учёта регистра и завершающей точки. Короткое имя принимается только при единственном совпадении. Отдельно показываются материалы с неизвестным узлом и расхождения площадок. Для авторизаций учитываются аудит последнего снимка, отдельно импортированные журналы и разделы авторизаций из выбранных обзоров. Количество событий относится к каждой выборке отдельно. Доступный источник с нулём событий отличается от отсутствующего журнала. Даты и фильтры выборки сверяйте с периодом обследования.

### Рабочая станция ALT

Задайте FQDN станции в `helper.node` её локальной конфигурации. Во время обследуемого сеанса выполните на станции:

```sh
sudo sambaadm-helper collect --profile alt-workstation \
  --config /etc/sambaadm-helper/config.yaml --site Region-01 \
  --account ivanov@corp.example --out /var/tmp/ws01-survey.json
```

Параметр `--account` необязателен. Импортируйте файл как «Снимок helper». В сводном отчёте станция появится в разделе §2.3 отдельно от перечня контроллеров.

- **DNS и регистрация.** Изучите настройки резолвера и ответ на диагностические запросы A/AAAA к FQDN станции. Строка SERVER в ответе dig показывает сервер этого запроса, в том числе локальный резолвер. Сопоставьте адреса ответа с активными интерфейсами. Журнал SSSD за последние сутки может содержать результат динамического обновления. Наличие записи само по себе не устанавливает, кто и когда её зарегистрировал.
- **DC и KDC.** sssctl показывает online/offline и активный сервер каждого обнаруженного домена SSSD (до восьми). Файл kdcinfo содержит адреса, предложенные локатором Kerberos. Снимок ss фиксирует существующие соединения до диагностических DNS-запросов. При отсутствии соединения с портом 88 сервер последней выдачи билета остаётся неизвестным.
- **Кэш.** Для домена сохраняются размер и время изменения базы SSSD, для указанного пользователя — вывод sssctl user-show. Они позволяют проверить наличие локальных данных. Возможность автономного входа проверяется отдельным испытанием.
- **GPO.** gpresult -c -m читает сохранённый результат последнего применения машинных политик. Пользовательские политики и запуск нового gpupdate в этот профиль не входят. [Описание GPResult в документации ALT](https://docs.altlinux.org/ru-RU/domain/10.4/html/alt-domain-p10/gpresult.html).

Для полного сбора нужны утилиты sssctl, gpresult, ip, ss и dig. Отсутствующие инструменты или недоступные данные отмечаются в наблюдениях. Сбор можно выполнять при отключённом канале до домена: неответившие DNS-запросы останутся видны как ограничение результата.

[Заполняемый протокол входа и сравнения снимков до и после изоляции](alt-sp-login-protocol.md).

## Карточка станции и сравнение снимков

Для профиля `alt-workstation` новый сборщик добавляет структурированную диагностику:

- SSSD: выбранные параметры доменной секции, провайдеры, discovery, основной и резервные серверы; права/владелец файлов; предупреждение о кавычках списка.
- Kerberos: `default_realm`, параметры DNS-поиска, сопоставления `domain_realm` и явные KDC в многострочных блоках `realms`. Читаются `/etc/krb5.conf`, абсолютные `include`/`includedir` и файлы из `KRB5_CONFIG`.
- Сохраняются только разрешённые параметры с проверенным форматом значений. Комментарии, неизвестные назначения и недопустимые значения исключаются с указанием количества; содержимое keytab и credential-кэшей не читается. Вывод `sssctl config-check` не экспортируется, поскольку может цитировать значения конфигурации.
- Ограничения: до 16 обычных файлов по 64 КиБ, без символьных ссылок; до 128 разрешённых назначений в файле. Сложный синтаксис, короткие имена realm и неполные чтения требуют локальной проверки. Снимок не является полной копией конфигурации и не определяет её эффективное слияние.

Карточка показывает источники, времена, предупреждения и количество наблюдений с данными. Часы источника и время приёма панелью показаны раздельно. Данные старше суток по часам панели требуют подтверждения актуальности; в изолированной сети этот возраст сам по себе не доказывает ошибку часов. Метаданные locator-плагина не доказывают, что библиотека его загрузила. Содержимое `kdcinfo` и SRV — кандидаты, а не доказательство выдачи конкретного билета.

### DNS через каждый резолвер

Укажите явные IP резолверов и запросы `FQDN/TYPE`:

```sh
sudo sambaadm-helper collect --profile alt-workstation \
  --config /etc/sambaadm-helper/config.yaml --site Region-01 \
  --dns-resolvers 192.0.2.53,192.0.2.54 \
  --dns-queries app.example.test/A,_kerberos._tcp.example.test/SRV \
  --out /var/tmp/ws01-survey-new.json
```

Поддерживаются A, AAAA, CNAME, SRV, SOA и NS; максимум четыре IP и восемь запросов. Каждый запрос выполняется отдельно по UDP и TCP, с тайм-аутом две секунды и четырьмя параллельными работниками. Это диагностические обращения от станции, запускаемые оператором через CLI; импорт файла не запускает сетевых проверок. Без обоих параметров матрица не собирается, что отмечается в карточке. Пароли и доменные изменения не требуются.

В ответе видны резолвер, имя/тип, транспорт, время, код DNS, записи с TTL и длительность. `observed + NXDOMAIN` означает полученный отрицательный ответ, `unknown` — отсутствие подтверждённого ответа, `partial` — усечённую выборку. Успешный DNS-ответ не подтверждает аутентификацию и не удостоверяет правильность целевого адреса: ожидаемые ответы сверяются оператором. Публичные источники не добавляются автоматически.

### Сравнение до и после

Выберите текущий снимок, откройте «Сравнить два снимка станции» и укажите более ранний. Сравниваются только снимки `alt-workstation` с одинаковым FQDN, без учёта регистра и завершающей точки. Разные площадки отмечаются предупреждением. Отсутствующее, частичное или недоступное наблюдение означает отсутствие достоверной пары, а не удаление настройки. DNS сравнивается отдельно для каждого резолвера и транспорта; уменьшение TTL не считается сменой целевого адреса. Длительность и TTL сохраняются в исходных данных.

Кнопка «Скачать снимок станции» сохраняет JSON, пригодный для повторного импорта. SHA-256 относится к файлу конкретного импорта; повторная сериализация может изменить его без изменения наблюдений. Экспорт не является подписанным пакетом происхождения. Проверяйте состав исходных журналов перед передачей: импорт принимает материалы администратора и не удостоверяет их автора.

Этот этап не меняет SSSD, Kerberos или внешний DNS, не проводит реальный вход и не отключает контроллеры. Редакторы профилей, адаптер кэширующего DNS, сопоставление событий входа и мастер отказов остаются следующим этапом.

Для структурированных снимков обновите helper и панель вместе: прежние строгие импортёры могут не знать поле `workstation`. Новая панель принимает прежние снимки и явно отмечает отсутствие расширенной диагностики.
