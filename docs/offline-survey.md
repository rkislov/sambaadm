# Автономное обследование домена

Выполните сбор локально на каждом согласованном Linux-узле с установленным helper. Для этого режима достаточно конфигурации с именем узла. Сервис HTTPS, SSH-доступ к узлу и пароль домена для запуска сбора не требуются. Площадку указывает оператор.

```sh
sudo sambaadm-helper collect --config /etc/sambaadm-helper/config.yaml \
  --site Region-01 --out /var/tmp/dc1-survey.json
```

Укажите новый путь. Helper создаёт файл с правами 0600. В снимке сохраняются имя узла, версия helper, начало и завершение сбора, источник, время и результат каждой локальной проверки. Собираются версия ОС, ядра и пакетов, выбранные параметры Samba, состояния служб, DNS-настройки резолвера, источники и смещение времени по данным chrony. Статус observed означает, что команда вернула данные. Состояние синхронизации и величину отклонения оценивают по содержимому. Для отсутствующих инструментов сохраняется unknown.

Если задан helper.auth_log, helper читает до 8 МиБ конца файла и сохраняет до 500 событий Samba Authentication с выбранными полями. Имена пользователей, рабочие станции, адреса, DN и время входа могут относиться к внутренним сведениям. Проверьте состав материалов и используйте согласованный канал передачи.

## Импорт

1. Войдите в sambaadm с ролью администратора. На главной странице откройте «Материалы автономного обследования» или перейдите к /surveys.
2. Выберите формат и файл размером до 16 МиБ. Для снимка helper узел и площадка берутся из самого файла. Для отдельного журнала укажите контроллер-источник и при необходимости площадку.
3. Нажмите «Импортировать». Материал появится в списке с временем импорта. В карточке доступны SHA-256 входного файла, наблюдения с их собственным временем и события авторизации.
4. Добавьте файлы других узлов. Для данных доменного уровня используйте JSON из кнопки «Скачать отчёт обследования JSON» в обзоре домена sambaadm. Он переносит уже собранные разделы топологии, репликации и диагностики. Количество разделов зависит от проверок, выполненных до экспорта.

Отдельный журнал принимается в формате Samba JSON audit, одно событие на строку, с допустимым текстовым префиксом. Сохраняются нормализованные поля Authentication, число ошибочных строк и признак ограничения выборки. Для отдельного журнала нужен хотя бы один распознанный вход. Пустой журнал в снимке helper отображается вместе со статусом источника. Для обзора домена сохраняется содержимое JSON-выгрузки. SHA-256 позволяет сверить исходный файл, а происхождение файла подтверждает передавшая его сторона.

## Хранение и границы первого этапа

Параметр server.survey_dir задаёт закрытый каталог sambaadm. По умолчанию используется /var/lib/sambaadm/surveys с правами 0700. Службе требуется право записи. Лимит — 128 материалов. Повторный импорт того же содержимого с теми же метками возвращает сохранённый материал. Срок хранения согласует администратор. После передачи архива администратор может удалить соответствующий файл ID.json из этого каталога.

Первый этап позволяет просматривать материалы по отдельности. Проверка фактического выбора DC рабочей станцией, корреляция результатов разных площадок и протокол испытаний до/после запланированы отдельно.

## Сводный отчёт

В разделе «Сводный отчёт по ТЗ» выберите материалы одного домена за согласованный период и нажмите «Сформировать отчёт». Наблюдения сгруппированы по площадке и узлу. Идентификатор в строке соответствует сохранённому материалу. Для сравнения версий ОС, Samba и chrony используется последний по времени завершения выбранный снимок каждой пары «площадка, узел». Расхождение версий требует оценки с учётом роли узла. Разделы обзора и журналы показывают доступность материалов. Охват площадок, успешность репликации и выводы о состоянии домена администратор подтверждает отдельно.
