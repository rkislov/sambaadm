# Безопасность

## Транспорт

- Production LDAP: только `ldaps://` или локальный `ldapi://`.
- Plain `ldap://` — только для изолированных лабораторий.
- Web UI: рекомендуется TLS (`server.tls.cert` / `key`).

## Секреты

- Пароль bind — `password_env` (по умолчанию `SAMBAADM_PASSWORD`), никогда в argv.
- Смена пароля пользователя: `--prompt` / интерактивный ввод.
- Файлы с секретами: права `0600`.

## Сессии и CSRF

- Cookie: `HttpOnly`, `SameSite=Lax`, `Secure` при TLS.
- Мутации (POST/PUT/PATCH/DELETE) требуют CSRF: поле `csrf_token` или заголовок `X-CSRF-Token`.

## RBAC

Роли из `memberOf` и `auth.roles` в YAML. Минимальный принцип привилегий: задайте группы Admins/Helpdesk явно.

## Аудит

Все мутирующие операции пишутся в `audit.file` (JSON lines) или в stderr. Просмотр: `/audit`.

## smb.conf / ACL

Изменение локального `smb.conf` и POSIX ACL выполняется **на хосте, где запущен sambaadm**, от имени процесса. Ограничьте `samba.shares_root` и права пользователя сервиса. `guest ok` на чувствительных шарах не включайте.

## Заголовки и поверхность атаки

- `/healthz`, `/metrics` — без сессии (не публикуйте metrics в интернет без защиты).
- OpenAPI `/api/docs` — справочный UI; в production при необходимости закройте reverse-proxy.

## Изоляция LDAP соединений веб-сервера

Проверка пароля и чтение групп пользователя выполняются на отдельном соединении, которое закрывается после входа. Пароль пользователя не сохраняется в веб-сессии. Общие операции каталога используют только настроенную служебную учётную запись `ldap.bind.user` и пароль из `password_env`.

Служебная запись обязательна для веб-входа. Если она не настроена, пароль отсутствует или Bind завершается ошибкой, сессия не создаётся. При ошибке поиска пользователя и его групп вход также отклоняется: приложение не назначает роль по запасному сценарию. При восстановлении оборванного соединения сначала повторяется Bind служебной записи; неподтверждённое соединение не передаётся обработчикам.

Выдавайте служебной записи только полномочия, необходимые для разрешённых операций. Роли приложения проверяются отдельно от прав записи в каталоге. Настройте группы ролей явно: сохранённое поведение первого запуска при пустом `auth.roles` даёт admin успешно аутентифицированному и найденному пользователю.

## RPM и резервные копии

Пакет использует системного пользователя sambaadm. EnvironmentFile остаётся
root:root 0600; YAML — root:sambaadm 0640. Снимки обновлений содержат секреты и
находятся в root-only `/var/lib/sambaadm-packages`, вне writable-каталогов сервиса.
Скрипт не скачивает и не исполняет shell-код из сети, не source-ит env и проверяет
RPM digest/signature. Для неподписанного RPM digest не устанавливает авторство:
сверяйте доверенные суммы или используйте корпоративную подпись. Откат приложения
не откатывает изменения каталога AD, SYSVOL и общих папок.

## Доверие sambaadm-helper

Операции ОС, файлов и SYSVOL выполняют helpers на управляемых узлах.
Управляющий процесс подписывает запросы Ed25519-ключом; закрытый ключ остаётся
на сервере sambaadm, открытые ключи доверия устанавливаются на helpers.
Проверяются имя узла, версия протокола, срок и уникальный ID запроса.
ID сохраняются в приватном state_dir и не становятся доступными для повтора
после перезапуска или через другой транспорт. Helper не предоставляет shell
или API произвольного запуска команд.

SSH проверяет host key и использует ограниченную команду; HTTPS использует
TLS 1.3 с проверкой сертификата. Основной сервер проверяет браузерные роли
и CSRF, helper доверяет подписавшему ключу как полномочию на свой набор
операций. События изменений сохраняются в аудитах основного сервера и helper.
Пути SYSVOL, шар, локальных ADMX и резервных копий ограничиваются конфигурацией
узла. [Установка, ключи и ротация](helper.md).
