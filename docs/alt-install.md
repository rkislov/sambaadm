# RPM: установка, обновление и откат на ALT Linux

## Единый комплект для новой установки

Выберите архив `sambaadm-install-ВЕРСИЯ-АРХИТЕКТУРА.tar.gz` из релиза с комплектами установки. Архитектуру покажет `uname -m`. Сверьте SHA-256 архива с SHA256SUMS этого релиза, распакуйте архив и перейдите в созданный каталог. В комплект входят оба RPM одной версии, установщик и инструкции.

```sh
sh setup-alt.sh all --check
sudo sh setup-alt.sh all
```

Режим `all` устанавливает приложение и локальный helper. Для центрального сервера только с приложением используйте `server`, для удалённого DC или узла автономного сбора — `helper`. Параметр `--check` проверяет выбор пакетов и моделирует транзакцию APT. Зависимости должны быть установлены или доступны в настроенных репозиториях ALT. Повторный запуск пропускает уже установленные компоненты той же версии.

### Автонастройка управляющего сервера

При первой интерактивной установке сервера на ALT с systemd установщик сам запускает мастер. Чтобы повторить его после исправления DNS или запустить отдельно, в каталоге комплекта выполните `sudo bash configure-server.sh`. Домен определяется по realm из локальной конфигурации Samba через testparm. Если realm отсутствует, проверяются поисковые DNS-домены из /etc/resolv.conf. Контроллер выбирается по SRV _ldap._tcp.dc._msdcs домена. При неоднозначности или отсутствии данных можно указать `--realm corp.example --dc dc1.corp.example`.

Команда `sambaadm discover` показывает предложенную конфигурацию без записи файлов. Base DN выводится из домена. Служебная запись по умолчанию — svc-sambaadm@домен, группа — Domain Admins в контейнере Users. Для другой структуры передайте мастеру `--user`, `--admin-group` и при необходимости `--ca /путь/к/ca.pem`. Проверьте предложенную группу перед вводом пароля.

Мастер предназначен для новой установки RPM с остановленной службой. Он запрашивает пароль без отображения, проверяет LDAPS Bind и чтение Base DN от имени пользователя службы и запускает sambaadm на 127.0.0.1:8080. Для удалённого доступа используйте SSH-туннель или HTTPS-прокси.

Проверьте запуск командой `systemctl is-active sambaadm`, затем откройте `http://127.0.0.1:8080/login` на сервере и войдите под доменной записью в формате UPN. Для подключения удалённого узла перейдите к [регистрации helper](helper.md#регистрация-через-веб-интерфейс). Для сбора с отключённой площадки достаточно [локального снимка](offline-survey.md).

Пакет для ALT p10/p11, x86_64 и aarch64, содержит статический бинарник,
`/lib/systemd/system/sambaadm.service` и `/usr/sbin/sambaadm-package`.
Сборка и пакетные сценарии проверяются в ALT p10, включая отдельный контейнер
с настоящим systemd. GPUI и работа на ALT СП 10.2.2 остаются отдельной приёмкой.

## Ручная установка отдельного RPM

Используйте RPM из доверенного источника; сравните SHA256SUMS по независимому
доверенному каналу. Проверка digest не доказывает авторство неподписанного RPM.
Для корпоративной поставки подпишите RPM своим ключом и импортируйте публичный
ключ в RPM. Скрипт не скачивает пакеты и не отключает проверку подписей.

На ALT установите зависимости из настроенного репозитория:

```sh
apt-get update
apt-get install bash coreutils tar util-linux shadow-utils systemd
# Скачайте sambaadm-package вместе с RPM из того же релиза:
sudo bash ./sambaadm-package install ./sambaadm-0.36.0-alt1.x86_64.rpm
sudoedit /etc/sambaadm/config.yaml
sudoedit /etc/sambaadm/env
sudo systemctl enable --now sambaadm.service
sudo journalctl -u sambaadm.service -n 100 --no-pager
```

В `/etc/sambaadm/env` укажите `SAMBAADM_PASSWORD='пароль служебной записи'`.
Это EnvironmentFile systemd, без `export` и shell-команд. Он принадлежит root,
права 0600; systemd передаёт пароль процессу, пользователь sambaadm файл не читает.
Настройте LDAP, доверенный CA и DN групп ролей в YAML; YAML имеет права 0640
root:sambaadm. Пакетный пример слушает **127.0.0.1:8080**. Для удалённого доступа
настройте TLS/обратный прокси и адрес явно.

Можно установить RPM напрямую через `apt-get install ./file.rpm` или `rpm -Uvh`,
но для первого контролируемого обновления потребуется сохранить RPM установленной
версии. Helper `install` сразу помещает его в root-only cache. В исходниках helper находится в `deploy/sambaadm-package`. Установка не
включает и не запускает службу. Пакетные скрипты не перезапускают её при обновлении;
управляемый перезапуск выполняет `sambaadm-package update`.

## Обновление

```sh
sudo sambaadm-package update ./sambaadm-0.36.0-alt1.x86_64.rpm
# Если предыдущая версия устанавливалась без helper:
sudo sambaadm-package update ./new.rpm --previous-rpm ./installed-version.rpm
```

Порядок: проверка RPM и архитектуры → тест транзакции → сохранение старого RPM,
конфигурации и systemd overrides → остановка → обновление → daemon-reload → запуск,
если сервис работал до обновления. Проверяется стабильный MainPID/NRestarts и
активность в течение пяти секунд. При ошибке установки или запуска возвращаются
предыдущий RPM и настройки; команда завершится с ошибкой, даже если восстановление
успешно. Эта проверка подтверждает запуск процесса, а не работоспособность домена;
после обновления запустите веб-диагностику и проверку входа.

Конфиги помечены `%config(noreplace)`: текущие YAML/env сохраняются, новый образец
при необходимости появляется как `.rpmnew`. Сравните изменения вручную. Новые
поля конфигурации не добавляются принудительно. Не выполняйте параллельно apt/rpm:
helper блокирует только собственные операции, RPM дополнительно защищает свою БД.

## Откат

```sh
sudo sambaadm-package list
sudo sambaadm-package rollback snapshot-20261028T120000Z-Ab12Cd
```

Используйте ID, выведенный **вашей** командой list. Откат устанавливает старый
RPM (`--oldpackage`), заменяет `/etc/sambaadm` и overrides unit их снимком и
возвращает состояние running/stopped на момент снимка. Перед откатом сохраняется
ещё один снимок для обратного перехода. Изменения настроек после снимка будут
заменены; они доступны в снимке, созданном перед откатом. Состояние enable/disable
сохраняется средствами systemd и helper его не переключает.

Снимки и кеш хранятся отдельно от каталогов, доступных пользователю сервиса:

- `/var/lib/sambaadm-packages/snapshot-*` — 0700 root, RPM, config.tar, метаданные;
- `/var/cache/sambaadm-packages/*.rpm` — RPM для последующего восстановления;
- `/run/lock/sambaadm-package.lock` — блокировка транзакций.

Архив конфигурации содержит пароли. Не публикуйте его. Снимки не очищаются
автоматически; удаляйте устаревшие вручную после приёмки. Внешние файлы CA/TLS,
на которые YAML ссылается вне `/etc/sambaadm`, резервируйте отдельно.

Откат **не восстанавливает AD, SYSVOL, файлы общих папок, smb.conf или журналы**.
Это откат приложения и его настройки. При выключении питания/убийстве процесса
посредине транзакции автоматическое восстановление может не сработать: проверьте
БД RPM, остановите сервис и используйте завершённый снимок вручную. Не применяйте
`--nodeps`/`--noscripts`/`--force` для обхода ошибок.

## Права сервиса и управляемый файловый сервер

Основной unit работает как `sambaadm`, с `ProtectSystem=strict`, `ProtectHome=true`, `NoNewPrivileges=true`. Запись разрешена в `/var/lib/sambaadm` и `/var/log/sambaadm`. Пользователь не получает root/sudo. LDAP, DNS и DRS используют служебную доменную запись приложения.

Начиная с v0.32.0 операции ОС, файлов и SYSVOL выполняет отдельный `sambaadm-helper`, в том числе на основном сервере. Установите соответствующий RPM на каждый управляемый Linux-узел, настройте доверенный открытый ключ и SSH либо HTTPS, затем зарегистрируйте узлы в `helpers.nodes`. Подробный порядок — [инструкция helper](helper.md) и [руководство администратора](admin.md).

Для нестандартных каталогов шаров настройте права ОС и `ReadWritePaths` в override **sambaadm-helper.service**, не основного unit. Права закрытого ключа подписи на управляющем сервере — 0600, конфигурация и состояние helper приватны для root. Обновление основного RPM не устанавливает и не обновляет helper на удалённых серверах. `sambaadm-package` управляет пакетом sambaadm; helper обновляйте отдельно через RPM/apt с сохранением конфигурации и контролируемым перезапуском HTTPS-службы.

## Переход с deploy/install.sh

Ручная установка использует `/usr/local/bin/sambaadm` и unit в `/etc/systemd/system`.
Helper откажется устанавливать RPM поверх неё, чтобы старый unit не перекрыл
пакетный. Сначала сохраните эти два файла и `/etc/sambaadm` в root-only резервную
копию, остановите сервис, переместите старый unit и бинарник из штатных путей,
выполните daemon-reload и установите RPM. YAML/env останутся на месте. Сверьте unit
и перенесите нужные изменения в drop-in; не копируйте старый ExecStart с
`/usr/local/bin`. Перед первым RPM-обновлением убедитесь, что кеш содержит RPM
текущей версии. Ручную установку не обновляйте скриптом поверх RPM.

## Сборка

```sh
# На рабочей машине с Go и Docker, внутри будет ALT p10:
make rpm-alt VERSION=0.36.0 RPM_ARCH=amd64
make rpm-alt VERSION=0.36.0 RPM_ARCH=arm64
# На ALT с готовым статическим ELF и rpm-build, file и systemd-analyze:
mkdir -p dist
bash packaging/alt/build-rpm.sh 0.36.0 ./sambaadm-linux-amd64 ./dist
```

Это пакет бинарной поставки, не исходный пакет Sisyphus: Go-бинарник собран вне
rpmbuild, зависимости Go не скачиваются в `%build`. Ветка СП может требовать своей
политики допуска и подписи; успешная сборка p10 не означает сертификацию СП.

Основание: [формат spec RPM](https://rpm.org/docs/latest/manual/spec.html),
[официальный образ ALT](https://hub.docker.com/_/alt/).

## Автоматическая сборка RPM и релизов

Общий workflow `.github/workflows/rpm-build.yml` используется CI и релизами.
RPM x86_64 и aarch64 собираются параллельно на нативных Ubuntu 24.04 x86/ARM
раннерах, в ALT p10. Сборочный Docker-образ кешируется отдельно для каждой
архитектуры через BuildKit/GitHub Actions cache.

Для APT используются `mirror.yandex.ru/altlinux`, `mirror.truenetwork.ru/altlinux`,
затем официальный `ftp.altlinux.org`. На зеркало: максимум 60 секунд на индексы и 180 секунд на
установку, с сетевым таймаутом 20 секунд и двумя повторами. Неуспешные индексы
удаляются перед переключением. Загружаются только native-архитектура и noarch.
Проверка подписей репозитория остаётся включённой. При недоступности всех
зеркал сборка завершается с ошибкой, а не публикует неполный релиз.

Зеркала можно задать при локальной сборке:

```sh
docker build --build-arg 'ALT_APT_MIRRORS=http://mirror.example/altlinux http://ftp.altlinux.org/pub/distributions/ALTLinux' \
  -t sambaadm-rpm-builder:p10-amd64 -f packaging/alt/Dockerfile .
```

В релизном workflow сначала собираются бинарники. RPM упаковывают именно эти
бинарники из artifact, включая восстановление executable-бита после скачивания.
Публикация зависит от успешных package/lifecycle/systemd-проверок обеих архитектур;
итоговый SHA256SUMS включает оба RPM, бинарники, helper и инструкцию.

Проверка без создания нового релиза:

```sh
gh workflow run release.yml --ref main -f version=0.36.0
```

Ручной запуск только сохраняет `release-verified` в Actions artifacts. Публикация
GitHub Release выполняется при push числового тега `vX.Y.Z` после всех проверок.
Текущий опубликованный релиз не перезаписывается пробным запуском.

В релизе v0.27.0 и новее архив `sambaadm-documentation-<version>.tar.gz` содержит актуальные Markdown-инструкции и иллюстрации. Для обслуживания сценариев GPO см. docs/admin.md в архиве: восстановление по журналу, копии и лимиты хранения, диагностика полномочий.

Согласованное делегирование использует закрытый локальный каталог `gpo.delegation_state_dir` (по умолчанию `/var/lib/sambaadm/delegation`, 0700). Сохраняйте его вместе с резервной копией состояния сервера; снимок конфигурации `sambaadm-package` не заменяет эту копию. Откат RPM не откатывает права в домене. Перед понижением версии завершите/откатите pending-операции в журнале делегирования.

## Обновление до v0.30.0

Добавлена проверка GPO → «Согласованность SYSVOL» на обнаруженных контроллерах. Новые параметры конфигурации и миграция данных не требуются. Служебной записи нужны права чтения LDAP/SYSVOL и ACL на проверяемых DC; сетевые имена и порты должны быть доступны с сервера приложения. Проверка не запускает репликацию и ничего не исправляет. Неполный отчёт не подтверждает согласованность домена.

В архив документации включены обновлённые инструкции API, Web UI, администратора и дорожная карта. Приёмка на целевом домене ALT СП 10.2.2 остаётся отдельным шагом после установки.

## Обновление до v0.31.0

Добавлено административное действие GPO → «Исправление SYSVOL»: явный выбор источника и одного целевого DC, предпросмотр файлов и ACL, сохранение исходной копии, завершение после сбоя и откат. Новые параметры конфигурации и миграция данных не требуются.

Перед использованием выделите окно обслуживания, остановите сторонние редакторы и синхронизаторы SYSVOL и используйте один активный экземпляр sambaadm. При переключении каталог GPO кратковременно отсутствует. LDAP не изменяется; его идентичность, версия, метаданные и безопасность должны совпадать на источнике и приёмнике. Копируются обычные файлы, владельцы, группы и DACL; SACL, альтернативные потоки и расширенные атрибуты не переносятся.

Служебной записи нужны права создания/переименования каталогов в SYSVOL/Policies и установки владельцев, групп и DACL. Журнал с исходными и желаемыми данными хранится в `gpo.delegation_state_dir/repair` (0700, файлы 0600); включите его в резервное копирование. Исходный каталог сохраняется на DC. Автоматической очистки архивов нет: контролируйте свободное место. Откат RPM не откатывает изменения SYSVOL — используйте журнал исправления.

Подробный порядок восстановления и ограничения приведены в docs/admin.md из архива документации. Приёмка на целевом домене ALT СП 10.2.2 остаётся отдельным шагом.


## Обновление до v0.33.0

Файловые операции теперь требуют настроенных helpers, прямой SMB из управляющего приложения не используется. Сначала подготовьте агенты на всех нужных DC и файловом сервере, сохраните прежнюю конфигурацию и журналы незавершённых операций, затем обновляйте основной пакет и добавляйте `helpers`. Без зарегистрированных узлов LDAP/DNS/DRS продолжают работать при наличии прав, но операции ОС/SYSVOL недоступны.

Добавлены управление Password Replication Policy по каждому RODC, принудительное заполнение кэша отдельных пользователей/компьютеров и просмотр локального JSON-аудита Authentication через helper. Источник preload — настроенный записываемый DC. Добавлена очистка старых архивов исправления SYSVOL по предпросмотру; по таймеру они не удаляются.

Релиз включает два Word-руководства и архив Markdown-инструкций с конфигурациями. Проверки выполнены на тестовом домене и ALT p10; это не приёмка реального домена или ALT СП 10.2.2.


## Обновление до v0.35.0

Установите основной пакет и отдельный `sambaadm-helper` версии 0.35.0 на все используемые узлы. `sambaadm-package` обновляет только основной пакет. Для SSH новый helper используется следующим запросом, для HTTPS перезапустите `sambaadm-helper.service`. Сохраните конфигурацию, ключи и `backup_root`; `%config(noreplace)` не включает новые возможности автоматически.

Для холодных копий на выбранном оставшемся RWDC явно включите `helper.domain_backup_enabled: true`. Нужны systemd, Python 3 и библиотеки Samba, отдельный `backup_root` и место для архива и двух восстановленных копий. Samba останавливает и запускает администратор. Рабочий LDAP приложения должен оставаться доступен через другой RWDC. Новый план очистки требует новой копии с изолированной пробной очисткой и повторным восстановлением; старые квитанции не принимаются.

Очистка поддержана для одного домена с минимум двумя остающимися RWDC, без RODC-реплик. Проверки холодного копирования выполнены на Samba 4.17/TDB; сборка и установка RPM на ALT p10 не заменяют приёмку этой функции на целевой ALT СП 10.2.2. Откат пакета не восстанавливает удалённые объекты AD. Полный порядок и ограничения приведены в [руководстве администратора](admin.md).

В 0.35.0 требуется место также в частном /tmp службы для временного образа DC. Разместите конфигурацию, данные Samba и backup_root вне /tmp, /var/tmp и /run. После обновления создайте свежую копию и дождитесь успешных проверок NTLM и Kerberos.
