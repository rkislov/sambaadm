# RPM: установка, обновление и откат на ALT Linux

Пакет для ALT p10/p11, x86_64 и aarch64, содержит статический бинарник,
`/lib/systemd/system/sambaadm.service` и `/usr/sbin/sambaadm-package`.
Сборка и пакетные сценарии проверяются в ALT p10, включая отдельный контейнер
с настоящим systemd. GPUI и работа на ALT СП 10.2.2 остаются отдельной приёмкой.

## Первая установка

Используйте RPM из доверенного источника; сравните SHA256SUMS по независимому
доверенному каналу. Проверка digest не доказывает авторство неподписанного RPM.
Для корпоративной поставки подпишите RPM своим ключом и импортируйте публичный
ключ в RPM. Скрипт не скачивает пакеты и не отключает проверку подписей.

На ALT установите зависимости из настроенного репозитория:

```sh
apt-get update
apt-get install bash coreutils tar util-linux shadow-utils systemd
# Скачайте sambaadm-package вместе с RPM из того же релиза:
sudo bash ./sambaadm-package install ./sambaadm-0.29.0-alt1.x86_64.rpm
sudoedit /etc/sambaadm/config.yaml
sudoedit /etc/sambaadm/env
sudo systemctl enable --now sambaadm.service
sudo journalctl -u sambaadm.service -n 100 --no-pager
```

В `/etc/sambaadm/env` укажите `SAMBAADM_PASSWORD='пароль служебной записи'`.
Это EnvironmentFile systemd, без `export` и shell-команд. Он принадлежит root,
права 0600; systemd передаёт пароль процессу, пользователь sambaadm файл не читает.
Настройте LDAP, доверенный CA и DN групп ролей в YAML; YAML имеет права 0640
root:sambaadm. Пакетный пример слушает **127.0.0.1:8080**. Для удалённого доступа
настройте TLS/обратный прокси и адрес явно.

Можно установить RPM напрямую через `apt-get install ./file.rpm` или `rpm -Uvh`,
но для первого контролируемого обновления потребуется сохранить RPM установленной
версии. Helper `install` сразу помещает его в root-only cache. В исходниках helper находится в `deploy/sambaadm-package`. Установка не
включает и не запускает службу. Пакетные скрипты не перезапускают её при обновлении;
управляемый перезапуск выполняет `sambaadm-package update`.

## Обновление

```sh
sudo sambaadm-package update ./sambaadm-0.29.0-alt1.x86_64.rpm
# Если предыдущая версия устанавливалась без helper:
sudo sambaadm-package update ./new.rpm --previous-rpm ./installed-version.rpm
```

Порядок: проверка RPM и архитектуры → тест транзакции → сохранение старого RPM,
конфигурации и systemd overrides → остановка → обновление → daemon-reload → запуск,
если сервис работал до обновления. Проверяется стабильный MainPID/NRestarts и
активность в течение пяти секунд. При ошибке установки или запуска возвращаются
предыдущий RPM и настройки; команда завершится с ошибкой, даже если восстановление
успешно. Эта проверка подтверждает запуск процесса, а не работоспособность домена;
после обновления запустите веб-диагностику и проверку входа.

Конфиги помечены `%config(noreplace)`: текущие YAML/env сохраняются, новый образец
при необходимости появляется как `.rpmnew`. Сравните изменения вручную. Новые
поля конфигурации не добавляются принудительно. Не выполняйте параллельно apt/rpm:
helper блокирует только собственные операции, RPM дополнительно защищает свою БД.

## Откат

```sh
sudo sambaadm-package list
sudo sambaadm-package rollback snapshot-20261028T120000Z-Ab12Cd
```

Используйте ID, выведенный **вашей** командой list. Откат устанавливает старый
RPM (`--oldpackage`), заменяет `/etc/sambaadm` и overrides unit их снимком и
возвращает состояние running/stopped на момент снимка. Перед откатом сохраняется
ещё один снимок для обратного перехода. Изменения настроек после снимка будут
заменены; они доступны в снимке, созданном перед откатом. Состояние enable/disable
сохраняется средствами systemd и helper его не переключает.

Снимки и кеш хранятся отдельно от каталогов, доступных пользователю сервиса:

- `/var/lib/sambaadm-packages/snapshot-*` — 0700 root, RPM, config.tar, метаданные;
- `/var/cache/sambaadm-packages/*.rpm` — RPM для последующего восстановления;
- `/run/lock/sambaadm-package.lock` — блокировка транзакций.

Архив конфигурации содержит пароли. Не публикуйте его. Снимки не очищаются
автоматически; удаляйте устаревшие вручную после приёмки. Внешние файлы CA/TLS,
на которые YAML ссылается вне `/etc/sambaadm`, резервируйте отдельно.

Откат **не восстанавливает AD, SYSVOL, файлы общих папок, smb.conf или журналы**.
Это откат приложения и его настройки. При выключении питания/убийстве процесса
посредине транзакции автоматическое восстановление может не сработать: проверьте
БД RPM, остановите сервис и используйте завершённый снимок вручную. Не применяйте
`--nodeps`/`--noscripts`/`--force` для обхода ошибок.

## Права сервиса и локальный файловый сервер

Unit работает как `sambaadm`, с `ProtectSystem=strict`, `ProtectHome=true`,
`NoNewPrivileges=true`. Запись разрешена в `/var/lib/sambaadm` и `/var/log/sambaadm`.
Пользователь не получает root/sudo. Удалённые AD-операции используют служебную
доменную учётную запись и не требуют локальных Samba/CUPS-утилит.

Для локальных шаров создайте ограниченный systemd override:

```ini
# systemctl edit sambaadm.service
[Service]
ReadWritePaths=/etc/samba /srv/samba
```

Разрешение записи в sandbox само по себе не выдаёт POSIX-права. Настройте ACL на
нужные каталоги отдельно; chown произвольных владельцев, reload Samba и администрирование
CUPS могут требовать других привилегий. Не выдавайте приложению неограниченный sudo.
Веб-диагностика показывает доступность локальных утилит/путей. Изменение overrides:
`systemctl daemon-reload` и `systemctl restart sambaadm`.

## Переход с deploy/install.sh

Ручная установка использует `/usr/local/bin/sambaadm` и unit в `/etc/systemd/system`.
Helper откажется устанавливать RPM поверх неё, чтобы старый unit не перекрыл
пакетный. Сначала сохраните эти два файла и `/etc/sambaadm` в root-only резервную
копию, остановите сервис, переместите старый unit и бинарник из штатных путей,
выполните daemon-reload и установите RPM. YAML/env останутся на месте. Сверьте unit
и перенесите нужные изменения в drop-in; не копируйте старый ExecStart с
`/usr/local/bin`. Перед первым RPM-обновлением убедитесь, что кеш содержит RPM
текущей версии. Ручную установку не обновляйте скриптом поверх RPM.

## Сборка

```sh
# На рабочей машине с Go и Docker, внутри будет ALT p10:
make rpm-alt VERSION=0.29.0 RPM_ARCH=amd64
make rpm-alt VERSION=0.29.0 RPM_ARCH=arm64
# На ALT с готовым статическим ELF и rpm-build, file и systemd-analyze:
mkdir -p dist
bash packaging/alt/build-rpm.sh 0.29.0 ./sambaadm-linux-amd64 ./dist
```

Это пакет бинарной поставки, не исходный пакет Sisyphus: Go-бинарник собран вне
rpmbuild, зависимости Go не скачиваются в `%build`. Ветка СП может требовать своей
политики допуска и подписи; успешная сборка p10 не означает сертификацию СП.

Основание: [формат spec RPM](https://rpm.org/docs/latest/manual/spec.html),
[официальный образ ALT](https://hub.docker.com/_/alt/).

## Автоматическая сборка RPM и релизов

Общий workflow `.github/workflows/rpm-build.yml` используется CI и релизами.
RPM x86_64 и aarch64 собираются параллельно на нативных Ubuntu 24.04 x86/ARM
раннерах, в ALT p10. Сборочный Docker-образ кешируется отдельно для каждой
архитектуры через BuildKit/GitHub Actions cache.

Для APT используются `mirror.yandex.ru/altlinux`, `mirror.truenetwork.ru/altlinux`,
затем официальный `ftp.altlinux.org`. На зеркало: максимум 60 секунд на индексы и 180 секунд на
установку, с сетевым таймаутом 20 секунд и двумя повторами. Неуспешные индексы
удаляются перед переключением. Загружаются только native-архитектура и noarch.
Проверка подписей репозитория остаётся включённой. При недоступности всех
зеркал сборка завершается с ошибкой, а не публикует неполный релиз.

Зеркала можно задать при локальной сборке:

```sh
docker build --build-arg 'ALT_APT_MIRRORS=http://mirror.example/altlinux http://ftp.altlinux.org/pub/distributions/ALTLinux' \
  -t sambaadm-rpm-builder:p10-amd64 -f packaging/alt/Dockerfile .
```

В релизном workflow сначала собираются бинарники. RPM упаковывают именно эти
бинарники из artifact, включая восстановление executable-бита после скачивания.
Публикация зависит от успешных package/lifecycle/systemd-проверок обеих архитектур;
итоговый SHA256SUMS включает оба RPM, бинарники, helper и инструкцию.

Проверка без создания нового релиза:

```sh
gh workflow run release.yml --ref main -f version=0.29.0
```

Ручной запуск только сохраняет `release-verified` в Actions artifacts. Публикация
GitHub Release выполняется при push числового тега `vX.Y.Z` после всех проверок.
Текущий опубликованный релиз не перезаписывается пробным запуском.

В релизе v0.27.0 и новее архив `sambaadm-documentation-<version>.tar.gz` содержит актуальные Markdown-инструкции и иллюстрации. Для обслуживания сценариев GPO см. docs/admin.md в архиве: восстановление по журналу, копии и лимиты хранения, диагностика полномочий.

Согласованное делегирование использует закрытый локальный каталог `gpo.delegation_state_dir` (по умолчанию `/var/lib/sambaadm/delegation`, 0700). Сохраняйте его вместе с резервной копией состояния сервера; снимок конфигурации `sambaadm-package` не заменяет эту копию. Откат RPM не откатывает права в домене. Перед понижением версии завершите/откатите pending-операции в журнале делегирования.
