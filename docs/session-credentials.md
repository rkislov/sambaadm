# Учётные данные текущей сессии для SYSVOL

В окне входа раскройте «Расширенные параметры». Опция «Моя учётная запись для
SYSVOL через helper» включена по умолчанию. При успешном входе пароль шифруется
AES-256-GCM с отдельным случайным nonce и привязкой к ID/имени сессии. Ключ
шифрования находится только в процессе sambaadm. Ни ключ, ни зашифрованные
записи не записываются в конфигурацию, cookie, localStorage или файлы состояния.
В cookie остаётся только случайный ID сессии.

Каждый запрос SYSVOL расшифровывает пароль на время передачи конкретному
зарегистрированному helper. Передача использует существующий HTTPS/SSH-канал,
а имя и пароль входят в подписанный запрос. Helper применяет их только для
локального SMB-доступа к SYSVOL; общая служебная запись и её пароль не меняются.
Операции ОС, метрик и шаров этих данных не получают. Для браузерного входа в
рабочем окружении используйте HTTPS.

При выходе и по таймеру истечения сессии зашифрованная запись удаляется, её
буфер очищается. Перезапуск приложения также теряет все сессии и ключ хранилища.
Фоновая доставка GPO хранит только ссылку на отзываемый источник сессии, а не
пароль. После выхода/истечения новые обращения за паролем завершаются ошибкой,
без перехода на настроенную служебную запись. Уже отправленный helper-запрос
может завершиться; пароль, который уже использует запрос, отозвать задним числом нельзя.
Хранилище не является защитой от полного захвата процесса sambaadm.

Обновите и sambaadm, и helper до v0.39.0. Запросы с данными сессии используют
расширение протокола 2: старый helper должен отклонить их, а не молча выполнять
операцию от другой записи. Запросы без пароля сохраняют совместимость с протоколом 1.
Ключи подписи и HTTPS-сертификаты переиздавать не требуется.

Если опция при входе выключена, действуют прежние ldap.bind.user и пароль самого
helper из helper.password_file или окружения. Для режима текущей сессии локальный
пароль helper не требуется. Если helper.password_file указан, файл по-прежнему
должен быть доступен службе при старте; для работы только с сессиями этот параметр
можно убрать. Входите с UPN (user@domain) либо DOMAIN\\user для SMB-аутентификации.

LDAP/RPC-операции основного приложения продолжают использовать настроенную
служебную запись. Сессия меняет только доменную аутентификацию SYSVOL на helper.
