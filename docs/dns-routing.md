# Делегирование, условная пересылка и DNS-бэкенд

Откройте **DNS → Делегирование и пересылка**. Настройки доступны администратору, все изменения требуют предпросмотра и подтверждения.

## Делегировать app.ipr.loc отдельному DNS

1. На отдельном DNS подготовьте зону `app.ipr.loc` и её записи.
2. Во вкладке **Делегирование** выберите родительскую зону `ipr.loc`.
3. Укажите поддомен `app` и DNS-серверы, по одному в строке:

   ```text
   ns1.app.ipr.loc 10.20.0.53
   ns2.app.ipr.loc 10.20.0.54
   ```

   Серверу внутри делегируемого поддомена нужны адресные записи (glue). Для внешнего NS, например `dns.other.loc`, укажите только DNS-имя: его адрес хранится в собственной зоне.
4. Откройте предпросмотр NS и glue, подтвердите и примените.

NS и адресные записи хранятся в AD и реплицируются вместе с родительской зоной. BIND9 DLZ на других DC читает те же записи из AD: повторно создавать их на каждом сервере не нужно. Дождитесь нормальной репликации перед проверкой всех DC.

В списке можно изменить или удалить делегирование. Удаление убирает только NS: адресные записи сохраняются, поскольку они могут использоваться другими объектами. При сбое нескольких DNS RPC обновлений показывается количество выполненных изменений; обновите список и повторите предпросмотр. Это не единая транзакция нескольких записей.

## Условная пересылка

Во вкладке **Условная пересылка** выберите домен, IP-адреса целевых DNS и режим:

- **Только указанные серверы** (`forward only`) — при их недоступности возвращается ошибка.
- **С рекурсивным резервом** (`forward first`) — BIND может продолжить обычное рекурсивное разрешение.

Для поддомена собственной AD-зоны **сначала создайте делегирование** на первой вкладке. Проверка с настоящим BIND9 DLZ подтвердила: без границы делегирования родительская AD-зона может ответить NXDOMAIN, и одной форвард-зоны недостаточно. Пересылка собственной AD-зоны или её родителя запрещена.

Выберите DNS-серверы доставки; по умолчанию выбраны все обнаруженные работающие BIND. Недоступные и неподдерживаемые узлы показаны с причиной и исключены из выбора. Предпросмотр проверит каждый выбранный сервер. Если хотя бы один недоступен или не поддерживает BIND, применение не начнётся: обновите helper, настройте бэкенд или явно исключите узел из доставки.

На каждом сервере меняется только выбранное правило; остальные управляемые правила сохраняются. При доставке показывается результат каждого узла. Сбой одного узла не отменяет успешные изменения остальных: повторите предпросмотр и доставку для неуспешных серверов.

Эти правила локальны для BIND и **не реплицируются через AD**. Доставка через helper нужна на каждом используемом BIND9 DLZ DC, включая вновь добавленные контроллеры.

Helper находит работающий BIND через `rndc status`, проверяет конфигурацию `named-checkconf`, сохраняет резервную копию и выполняет `rndc reconfig`. В случае ошибки пытается восстановить прежний файл. Сторонние настройки вне блока sambaadm не переписываются. Вручную изменённый управляемый блок требует проверки, автоматическая перезапись блокируется.

Переопределение пути для нестандартной установки:

```yaml
helper:
  dns_config: /etc/bind/named.conf
```

Встроенный DNS Samba не поддерживает такие форвард-зоны. Для него доступны делегирования; для условной пересылки переключите выбранный DC на BIND9 DLZ.

## Установка, переустановка и возврат бэкенда

Вкладка **DNS-бэкенд** предназначена для контроллеров ALT Linux:

1. Выберите DC и целевой бэкенд: **BIND9 DLZ** или **встроенный DNS Samba**.
2. Если нужно, отметьте **Переустановить пакеты BIND**. Используются пакеты `bind` и `bind-utils` из уже настроенных репозиториев ALT. Samba через этот мастер не обновляется.
3. Изучите предпросмотр и подтвердите кратковременный перерыв DNS и Samba на этом DC.
4. Следите за журналом. Задание выполняется отдельной systemd-службой и продолжается после закрытия вкладки; его ID сохраняется в браузере для повторного открытия журнала.

Helper сохраняет закрытые резервные копии конфигурации, вызывает штатный `samba_upgradedns`, выбирает DLZ-модуль для установленной версии BIND, проверяет конфигурацию и ответы SOA/SRV LDAP. При ошибке пытается восстановить прежний бэкенд и конфигурацию. Журнал сообщает о неполном откате; резервные копии остаются в `helper.state_dir/dns-backend/ID/`.

AD-зоны остаются в каталоге. Возврат на встроенный DNS останавливает BIND на выбранном DC; конфигурация пересылок сохраняется, но правила перестают действовать. Пакеты BIND не удаляются, чтобы можно было вернуться обратно. Операция относится к одному DC, остальные контроллеры продолжают работать.

Мастер не является полной резервной копией контроллера и не откатывает установленные версии RPM. Конфигурации Samba с include/registry требуют отдельного согласования: мастер не переписывает их автоматически. Перед переключением рабочей системы проверьте резервное копирование и наличие доступного второго DC.

## Проверка результата

С клиентской станции проверьте каждый DNS/DC:

```sh
dig @IP_КОНТРОЛЛЕРА app.ipr.loc NS
dig @IP_КОНТРОЛЛЕРА service.app.ipr.loc A
dig @IP_КОНТРОЛЛЕРА ipr.loc SOA
dig @IP_КОНТРОЛЛЕРА _ldap._tcp.ipr.loc SRV
```
