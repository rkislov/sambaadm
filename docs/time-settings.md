# Время и NTP

Страница `/settings/time` доступна администратору в разделе «Настройки → Время и NTP». Она работает через зарегистрированный Linux `sambaadm-helper` выбранного узла. На сервере панели команды времени как запасной вариант не выполняются.

Экран показывает часы узла, вывод `chronyc -n tracking`, `chronyc -n sources` и состояние службы. Активная служба не означает синхронизацию. Показания получены от часов самого узла; точность UTC и взаимное расхождение нескольких узлов этой страницей не измеряются.

## Включение изменений

По умолчанию доступно только чтение. В доверенной конфигурации helper на управляемом узле укажите фактический файл и службу:

```yaml
helper:
  time_config: /etc/chrony.conf
  time_service: chronyd.service
```

Используется существующий файл до 64 КиБ. Файл должен быть обычным, без символьной ссылки. Допускаются службы `chronyd.service` и `chrony.service`; необходимо проверить, что выбранная служба читает именно указанный файл. Для изменения и перезапуска helper нужны соответствующие системные права. Настройки не распространяются на другие узлы автоматически.

## Изолированная сеть

Внешний источник не обязателен. Можно назначить один узел внутренней опорой: режим «Изолированный стенд», локальная опора, stratum 8–14, явные клиентские CIDR-подсети. Другие узлы получают внутренний адрес через `server адрес iburst`. Автоматического выбора лидера и защиты от двух независимых опор здесь нет: внутреннюю иерархию необходимо спроектировать заранее.

Локальная опора обеспечивает общую шкалу внутри сети, но не удостоверяет точность UTC. Ручная установка даты, часового пояса и RTC в эту версию не входит. Файрвол, GPO клиентов и конфигурация Proxmox не меняются.

## Проверка и применение

1. Выберите узел и прочитайте состояние.
2. Задайте источники и клиентские подсети. Поддерживается `server|pool|peer адрес [iburst] [prefer]`. Общий доступ `/0` запрещён.
3. Нажмите «Проверить и показать изменения». Временный файл проверяется `chronyd -p -f`; действующий файл не заменяется.
4. Проверьте полный текст и подтвердите применение. Сравниваются хеши текущего и предложенного файлов: устаревший предпросмотр отклоняется.
5. Создаётся приватная резервная копия в каталоге конфигурации, файл заменяется и служба перезапускается. Если перезапуск или проверка активности неудачны, выполняется попытка возврата прежнего файла и повторного запуска. При внешнем изменении файла автоматический откат останавливается. Ошибка содержит путь резервной копии.
6. Повторно проверьте реальную синхронизацию и работу доменной аутентификации. Успешный перезапуск не подтверждает эти результаты.

Панель сохраняет остальные директивы. **Существующий `makestep` может привести к скачку часов после перезапуска chrony.** Отдельная команда `makestep` не вызывается. Перед применением проверьте полный файл и выберите подходящее окно работ. Сложные источники, включаемые конфигурации, `refclock`, `initstepslew` и `deny` переводят настройку в режим чтения; их нужно обслуживать вручную.

## API

Все маршруты требуют сессии администратора; изменения также требуют CSRF. Параметр `node` — имя зарегистрированного helper.

- `GET /api/v1/system/time?node=...` — состояние и доступность редактирования.
- `POST /api/v1/system/time/plan?node=...` — проверка и предпросмотр.
- `PUT /api/v1/system/time?node=...` — применение подтверждённого предпросмотра.

Пример тела плана:

```json
{"settings":{"mode":"isolated","sources":[],"localReference":true,"stratum":10,"allow":["10.0.1.0/24"]}}
```

Для применения добавьте поля `revision`, `proposedRevision` из ответа плана и `confirm: true`. Само поле `settings` должно оставаться тем же. Результат содержит путь резервной копии и новое наблюдаемое состояние. Операция применения записывается в аудит панели и helper.

Справочные материалы: [chronyd — режим проверки конфигурации](https://chrony-project.org/doc/4.6/chronyd.html), [директивы chrony](https://chrony-project.org/doc/4.6/chrony.conf.html). Совместимость с установленной версией подтверждается локальной проверкой синтаксиса; интеграционное испытание на целевой ОС требуется перед эксплуатацией.
