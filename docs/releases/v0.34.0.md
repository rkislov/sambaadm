# v0.34.0 — очистка остатков DC с проверкой восстановления

Очистка подтверждённых остатков контроллеров и связей LDAP по проверенному плану, с резервной копией и контролем результата на оставшихся RWDC.

- Предпросмотр пустых сайтов, устаревших связей, NTDS Settings, разрешённых RID/DFSR-поддеревьев и связанных DNS-записей выведенных DC. Общие DNS-узлы сохраняют значения других контроллеров.
- Проверки зависимостей, FSMO, совпадения объектов и репликации; отдельное подтверждение окончательного вывода DC. Недоступность или возраст записи сами по себе не разрешают удаление.
- Новый sambaadm-helper: выборочный снимок, полная холодная копия остановленного RWDC, пробная очистка в изоляции и повторное восстановление того же архива с проверкой GUID, атрибутов, базы и SYSVOL ACL.
- Применение с LDAP assertions и журналом до/после каждой операции. Синхронизация доменного раздела, Configuration, DomainDnsZones и ForestDnsZones, запуск KCC и проверка оставшихся RWDC. При конфликте выполнение останавливается; автоматического отката в рабочий домен нет.
- Рабочие операции без samba-tool: заполнение кэша RODC и работа с копиями используют библиотеки Samba напрямую. Исправлено освобождение SMB/RPC-соединений при отмене запросов.
- Обновлённые инструкции администратора и пользователя в Markdown и Word. Время в интерфейсе отображается с часовым поясом браузера; JSON сохраняет машинный формат.

## Обновление

Обновите **sambaadm и sambaadm-helper до 0.34.0**. Они поставляются отдельными бинарниками и RPM. `sambaadm-package` обновляет только основное приложение; helper обновляется отдельно. Перед обновлением сохраните конфигурацию, ключи и состояние обоих компонентов. После обновления HTTPS helper перезапустите его службу; SSH запустит новый бинарник следующим запросом.

Холодные копии включаются явно: `helper.domain_backup_enabled: true`. Нужны systemd, Python 3 с библиотеками Samba, `backup_root` вне каталогов Samba и место для архива и двух развёрнутых копий. Остановку и запуск Samba выполняет администратор в окне обслуживания; LDAP приложения в это время должен работать через другой RWDC. Старые квитанции восстановления не допускают применение новых планов: создайте новую копию с проверкой повторного восстановления.

[Инструкция администратора](https://github.com/rkislov/sambaadm/blob/v0.34.0/docs/admin.md), [инструкция пользователя](https://github.com/rkislov/sambaadm/blob/v0.34.0/docs/user.md), [настройка helper](https://github.com/rkislov/sambaadm/blob/v0.34.0/docs/helper.md).

## Границы применения и проверки

Очистка рассчитана на один домен с минимум двумя остающимися RWDC и максимум 16 зарегистрированными контроллерами. RODC-реплики и удаление NTDS RODC требуют отдельного сценария. Проверенная платформа холодного копирования — Samba 4.17/TDB; MDB, Windows DC и целевая ALT СП 10.2.2 требуют отдельной приёмки. Сборка RPM на ALT p10 не заменяет эту приёмку.

Последняя NS, SOA с удаляемым DC как primary, общий IP другого имени, действующий DC, FSMO, неизвестные дети и несогласованные реплики блокируют план. Лимиты: 50 выбранных находок, 150 объектов после расширения, 10 000 DNS-узлов, копия моложе 24 часов. Архив содержит доменные секреты и остаётся на helper; формат `sambaadm-cold-dc-v1` предназначен для восстановления того же DC. Восстановленный образ нельзя подключать рядом с исходным DC в рабочей сети.

Проверены Go-тесты с race detector, vet, браузерные сценарии, очистка на двух Samba DC, остановка при конфликте, изолированное восстановление и запуск восстановленного DC с проверкой входа. Проверки восстановления и применения выполняются отдельными стендовыми сценариями. Сборка релиза проверяет бинарники и жизненный цикл RPM для x86-64 и ARM64.
