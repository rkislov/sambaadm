# sambaadm 0.53.0 — первый RWDC существующего домена

В первоначальном HTTPS-мастере появился сценарий установки первой панели и Samba RWDC в уже существующем AD. Он сохраняет домен, ожидает получение каталога, отдельно копирует SYSVOL с проверкой файлов и прав, затем настраивает панель и локальный helper.

## Возможности

- Обнаружение NetBIOS, сайта, SID и функциональных уровней исходного RWDC через Kerberos. Неподдерживаемые уровни блокируются без изменения AD.
- До получения каталога и SYSVOL новый DC доступен только локально. Проверяются все разделы AD, объекты, версии GPO и права файлов.
- HTTPS с доменным именем панели, отдельная новая служебная запись и привязка helper.
- Перенос FSMO по явному выбору, выключенному по умолчанию; результат по каждой роли. Обычный перенос без захвата и без отключения исходного DC.
- Продолжение настройки панели после сбоя с проверкой идентичности RWDC. Присоединение и SYSVOL не повторяются, чужие конфиги и служебные записи не заменяются.
- Исправлен сброс предпросмотра при вводе доменного логина на шаге подтверждения.
- Русская инструкция по пилоту, совместной работе SYSVOL и штатному выводу Windows DC; ссылка из меню «Домен и FSMO».

## Статус совместимости

**Настоящий Windows DC ещё не проверен: тестовый Windows Server пока отсутствует.** Протокольные проверки выполняются на изолированном Samba AD на ALT p10/p11. Нельзя считать этот релиз приёмкой миграции рабочего Windows AD.

Начальное копирование SYSVOL не включает постоянную DFSR-репликацию Windows–Samba. Отдельный интерфейс повторной синхронизации Windows SYSVOL в этот релиз не входит. До подтверждения политик и входа клиентов оставляйте исходный DC включённым.
