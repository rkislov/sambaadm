# v0.37.0 — предзаполнение config.yaml для бинарной установки

При первом запуске `sambaadm serve` без конфигурации приложение определяет домен по локальной Samba или DNS, выбирает контроллер по SRV и создаёт `config.yaml`. Предзаполняются LDAPS URI, Base DN, имя служебной записи, группа администраторов и регистрация HTTPS-helper через веб-интерфейс. По умолчанию интерфейс слушает 127.0.0.1:8080.

Команда `sambaadm discover --output config.yaml` сохраняет настоящий YAML. Параметры `--realm`, `--dc`, `--user`, `--admin-group` и `--ca` позволяют явно задать окружение. Существующий файл, включая символическую ссылку, не перезаписывается; новый файл получает права 0600. Родительский каталог должен существовать. Без `--output` команда выводит YAML в stdout.

Установщик `deploy/install.sh` также пытается предзаполнить конфигурацию перед установкой примера. При недоступном DNS он оставляет пример с сообщением о ручной настройке. Существующая конфигурация и env сохраняются. Порядок первоначальной настройки RPM через configure-server.sh не меняется.

Имя svc-sambaadm и DN группы — предлагаемые значения, требующие проверки. Автонастройка не создаёт доменную запись, не угадывает пароль и не отключает проверку TLS. Перед входом задайте пароль служебной записи в SAMBAADM_PASSWORD и настройте доверие к CA. Для работы нужны каталоги состояния и журналов с правами службы; для ручной установки Linux используйте deploy/install.sh. Проверка serve --check не создаёт файл.

Приложение и helper следует обновлять до одной версии. Изменений формата существующих конфигураций нет.
