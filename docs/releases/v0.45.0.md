# v0.45.0 — восстановление домена из полной копии

## Восстановление первого DC

Добавлен самостоятельный сценарий восстановления после **полной потери однодоменного леса** из архива `sambaadm-cold-dc-v1`.

- В разделе «Резервные копии» появился экран восстановления: выбор helper, UUID полной копии, нового имени DC и IPv4; проверка архива и предпросмотр исходного домена, времени/размера копии, SHA-256 и целевых путей.
- Восстановление создаёт **новый каталог и новый RWDC с новым именем**. Штатный механизм установленной Samba создаёт новую DSA/invocation ID, восстанавливает FSMO/RID, удаляет прежние DC и репликационные связи и дважды меняет krbtgt.
- Пользователи, группы, SID/GUID, пароли и содержимое SYSVOL возвращаются к моменту копии. Изменения после создания копии теряются; некоторым компьютерам может потребоваться восстановление доверия.
- Восстанавливаются NT/POSIX-права SYSVOL, включая корневой каталог и хранилище `xattr_tdb`. Выполняется штатное заполнение SPN нового DC.

## Работа без LDAP

При недоступности домена, истечении веб-сессии или потере управляющего сервера доступны локальные root-команды:

```sh
sambaadm-helper domain-restore-plan --config /etc/sambaadm-helper/config.yaml \
  --backup-id <UUID-копии> --new-name RECOVER --address <IPv4>

sambaadm-helper domain-restore --config /etc/sambaadm-helper/config.yaml \
  --id <UUID-плана> --revision <revision> \
  --confirm-domain-lost --confirm-isolated

sambaadm-helper domain-restore-status --config /etc/sambaadm-helper/config.yaml \
  --id <UUID-плана>
```

Команды не требуют LDAP, доменного пароля или ключа управляющего сервера. Веб-операции и API доступны администратору; POST защищён CSRF и записывается в аудит.

Новые API: `POST /api/v1/backups/restore/plan`, `POST /api/v1/backups/restore/start`, `GET /api/v1/backups/restore/status` с параметром `node`.

## Проверки и защита данных

- Нужна завершённая самостоятельная полная копия с квитанцией успешного пробного восстановления; архивы очистки топологии не принимаются. SHA-256 пересчитывается перед подготовкой и запуском.
- План действует один час. Требуются подтверждения полной потери домена, остановки всех прежних DC, изоляции узла и совместимости Samba.
- Повтор того же запроса возвращает ту же задачу. Существующий целевой каталог не перезаписывается; частичные результаты и приватные логи сохраняются для диагностики.
- Задание работает через systemd в отдельной сети с приватным `/run` и лимитом 30 минут. В постоянной кандидатной базе тестовый пользователь не создаётся.
- Изолированная копия восстановленного кандидата проходит dbcheck, проверку идентичности домена, новой invocation ID, единственной DSA и всех семи FSMO, а также вход LDAP, отказ с неправильным паролем, SMB SYSVOL и Kerberos TGT/LDAP/CIFS без NTLM-fallback. Данные кандидата синхронизируются на диск перед статусом `ready`.
- Новые полные архивы записывают версию Samba. Для архивов v0.44.0 без этого поля совместимость версии проверяется оператором отдельно.

## Условия обновления и эксплуатации

Обновите **оба компонента**: `sambaadm` и `sambaadm-helper`. По умолчанию восстановление отключено. На изолированном Linux-узле восстановления нужны systemd, Python-модули Samba, `samba-tool`, `samba_spnupdate`, достаточное место для нескольких развёрнутых копий и настройки:

```yaml
helper:
  domain_backup_enabled: true
  backup_root: /var/lib/sambaadm-helper/backups
  domain_restore_enabled: true
  domain_restore_root: /var/lib/sambaadm-recovery
```

Все прежние контроллеры должны оставаться выключенными; затем их переустанавливают и вводят в восстановленный домен заново. Для замены одного DC среди работающих реплик используйте штатный ввод нового контроллера.

Проверенный сценарий — **Samba 4.17.12/TDB, однодоменный лес**. MDB, многодоменные леса и переименование домена не поддерживаются. Это восстановление в новый каталог; конфигурация ОС, DNS, службы и ввод DC в рабочую сеть выполняются вручную после `ready`. Рабочая база не перезаписывается, служба автоматически не запускается.

## Проверки выпуска

- Тесты Go с `-race`, `go vet`, проверка встроенного CSS и браузерные сценарии.
- Контейнерный сценарий восстановления архива с двумя прежними DC: новая DSA/invocation, FSMO, удаление старых DC, смена krbtgt, сохранение пользовательских SID/GUID/хеша пароля, Kerberos/LDAP/SYSVOL.
- Проверки неизменности исходных файлов и архива, отказа при неверной контрольной сумме, старом имени DC и существующей цели.
- Сохранены регрессионные проверки полного холодного бэкапа и его изолированного восстановления.
