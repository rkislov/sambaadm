# sambaadm-helper

`sambaadm-helper` — отдельный пакет и процесс на каждом управляемом сервере,
включая основной файловый сервер. Sambaadm сохраняет веб-интерфейс, вход,
RBAC, LDAP, DNS и DRS. Операции ОС, NSS, smb.conf, принтеров, ACL и файлов
SYSVOL выполняет helper соответствующего узла. Копирование политик читает
данные через helper источника и пишет через helper получателя. При отсутствии
helper запись напрямую по SMB не выполняется.

Поддерживаются SSH и HTTPS. В обоих случаях запрос подписан Ed25519-ключом
сервера sambaadm и содержит имя узла, версию протокола, время и уникальный ID.
Helper хранит только доверенные открытые ключи. HTTPS требует TLS 1.3 с
проверкой сертификата; SSH требует отдельный транспортный SSH-ключ и заранее
проверенный `known_hosts`. Переадресация HTTPS и автоматическое принятие
SSH host key отключены. Произвольного запуска команд через API нет.

## Установка

Сборка бинарников: `make build`. Отдельный RPM:
`make rpm-helper-alt VERSION=0.34.0 RPM_ARCH=amd64` (также `arm64`). Используйте бинарники и RPM одной версии с управляющим приложением.

Установите RPM helper на нужные серверы. Пакет не запускает сервис и не
добавляет доверенных ключей автоматически. Настройка каждого узла:
`/etc/sambaadm-helper/config.yaml`, пример — `configs/helper.example.yaml`.
Для ручной установки скопируйте бинарник в `/usr/bin/sambaadm-helper`,
unit из `deploy/` в `/etc/systemd/system/`, пример конфигурации — в
`/etc/sambaadm-helper/config.yaml`. Каталоги конфигурации и состояния должны
быть root-only; создайте `/var/log/sambaadm-helper` и каталог `backup_root`.

Helper использует локальные системные утилиты и локальный SYSVOL через SMB
на `127.0.0.1`, сохраняя Samba security descriptors. Для файлов SYSVOL задайте
на каждом helper служебную доменную запись с нужными правами и её пароль в
`helper.password_file` (обычный root-only файл 0600 с одной строкой) либо в
переменной `ldap.bind.password_env` окружения процесса helper. Sambaadm не
передаёт этот пароль по управляющему каналу. Поле `helper.sysvol_prefix`
ограничивает файловые запросы, например `example.com/Policies`.

Для RODC preload нужны Python 3 и Python-модули Samba (`samdb`, `credentials`, `drs_utils`)
на самом RODC. Эта операция использует машинную учётную запись RODC и
проверяет локальный DSA GUID перед записью; пароли и хэши в ответ не входят.

## Ключ подписи на сервере sambaadm

Создайте ключ один раз на управляющем сервере:

```sh
sudo install -d -m 0750 -o root -g sambaadm /etc/sambaadm/keys
sudo sambaadm-helper keygen \
  --private /etc/sambaadm/keys/helper-signing.key \
  --public /etc/sambaadm/keys/helper-signing.pub
sudo chown sambaadm:sambaadm /etc/sambaadm/keys/helper-signing.key
```

Закрытый ключ остаётся здесь (0600). Передайте только `.pub` на управляемые
серверы и укажите его в `helper.trusted_keys`. Для ротации сначала добавьте
новый открытый ключ на helpers, затем переключите private_key в sambaadm и
после проверки удалите прежний открытый ключ из списка доверия. Для HTTPS перезапускайте helper после изменения списка доверия; SSH-процесс читает его при каждом запуске.

## HTTPS

В helper-конфигурации задайте уникальный FQDN в `helper.node`, адрес
`helper.listen`, сертификат и закрытый TLS-ключ в `helper.tls`. Сертификат
должен соответствовать имени в URL. Откройте порт для управляющего сервера,
затем запустите `systemctl enable --now sambaadm-helper`.

На сервере sambaadm:

```yaml
helpers:
  private_key: /etc/sambaadm/keys/helper-signing.key
  host_node: dc1.example.com
  nodes:
    - name: dc1.example.com
      transport: https
      endpoint: https://dc1.example.com:8444
      ca_cert: /etc/sambaadm/keys/helper-ca.pem
    - name: rodc1.example.com
      transport: https
      endpoint: https://rodc1.example.com:8444
      ca_cert: /etc/sambaadm/keys/helper-ca.pem
```

`host_node` выбирает сервер для файловых шар, NSS, локальных ADMX, метрик и
резервных копий. Имена DC в `nodes` должны совпадать с обнаруженными DNS-именами.
При использовании собственного CA его сертификат нужен на сервере sambaadm;
проверку TLS отключать нельзя.

## SSH

Сгенерируйте отдельный SSH-ключ для транспорта на сервере sambaadm и сохраните
его в доступном сервису каталоге `/etc/sambaadm/keys`. Заранее проверьте
SSH host key целевого сервера и сохраните его в отдельный known_hosts.

На helper-сервере для пользователя `sambaadm-agent` настройте root-owned
authorized_keys с принудительной командой:

```text
restrict,command="sudo -n /usr/bin/sambaadm-helper stdio" ssh-ed25519 AAAA... management-server
```

Путь authorized_keys можно задать в sshd как
`AuthorizedKeysFile /etc/ssh/authorized_keys/%u`. Доступ по паролю этому
пользователю не нужен. В root-owned файле sudoers 0440 разрешите только:

```text
sambaadm-agent ALL=(root) NOPASSWD: /usr/bin/sambaadm-helper stdio
```

Проверьте sudoers через `visudo -cf`. Не разрешайте shell и произвольные
аргументы helper. Root-конфигурация helper и доверенный ключ подписи нужны
также для SSH; один транспортный SSH-ключ не заменяет подпись протокола.

```yaml
helpers:
  private_key: /etc/sambaadm/keys/helper-signing.key
  host_node: dc1.example.com
  nodes:
    - name: dc1.example.com
      transport: ssh
      endpoint: sambaadm-agent@dc1.example.com
      ssh_key: /etc/sambaadm/keys/helper-ssh
      known_hosts: /etc/sambaadm/keys/helper-known-hosts
```

Сервис HTTPS для SSH-режима включать не требуется. На основном сервере
используется тот же SSH/HTTPS-канал к его helper. Основному процессу sambaadm
не требуется снимать `NoNewPrivileges` ради sudo.

## RODC и журнал

В «Сайты» или «Репликация» откройте «Кэш и авторизации RODC», выберите
контроллер. Разрешения PRP, запреты, кэшированные записи и список записей,
проходивших через RODC, показываются раздельно. Добавление/удаление назначений
и принудительное заполнение имеют предпросмотр и подтверждение. Для preload
выбираются отдельные пользователи/компьютеры; группы не разворачиваются.
Неизвестный полный токен и любое совпадение запрета блокируют заполнение.
Окончательное решение о репликации принимает Samba на RWDC.

Для работы с PRP настройте LDAP sambaadm на записываемый DC. Учётная запись
службы LDAP должна иметь соответствующие права; браузерный вход её не меняет.
Снятие разрешения или добавление запрета не стирает уже закэшированные пароли.

Для журнала задайте на helper выбранного RODC `helper.auth_log` и включите
Samba JSON-аудит, например `auth_json_audit:3@/var/log/samba/auth.json` в
`log level`, с файловым backend журналирования. Файл читается на самом RODC
через helper. Путь из HTTP-запроса пользователя не принимается. Доступны
фильтры времени и учётной записи, успешные/неуспешные Authentication-события,
клиент и служба. Читаются последние 8 MiB, выдаются до 500 подходящих событий;
усечение и повреждённые записи отмечаются. Успешная аутентификация не равна
интерактивному входу. Отсутствие источника, отключённый аудит или ротация
не доказывают отсутствие авторизаций.

## Эксплуатация

Helper работает с полномочиями для файлов и ACL; в поставляемом unit это root.
Операции ограничены фиксированным списком, SYSVOL-prefix, shares_root и
backup_root. Пути backup/restore теперь относятся к helper `host_node`.
Если шары размещены вне `/srv/samba`, настройте ReadWritePaths в override unit
helper. Аудит helper хранится отдельно; время на узлах должно быть согласовано.
Использованные ID запросов сохраняются в приватном state_dir, поэтому перезапуск HTTPS или новый SSH-процесс не разрешает повтор ранее принятого запроса. При потере ответа запись может быть уже выполнена: сначала проверьте состояние
или продолжите штатное восстановление по журналу, не повторяйте запись вслепую.


В v0.33.0 обзор контроллера использует новый read-only метод `host.inventory`:
фиксированные команды версии Samba и состояния известных systemd units, без
параметров команд от пользователя. Для него требуется обновить helper.
`helper.auth_log` и существующее чтение `rodc.auth` используются также для аудита
выбранного записываемого DC; проверка принадлежности DC каталогу и роль admin
выполняются в sambaadm. Период хранения и включение аудита проверяются отдельно.

### Снимки подготовки очистки LDAP

Методы `topology.snapshot.store` и `topology.snapshot.load` сохраняют и проверяют
подготовительные снимки в `helper.backup_root/topology-snapshots`. Каталог создаётся
с 0700, файлы — с 0600 и уникальными UUID; пути не принимаются от браузера.
Публичный каталог, символическая ссылка вместо каталога/файла, неверная контрольная
сумма или превышение 2 МиБ отклоняются. Запись синхронизируется на диск, после неё
sambaadm читает файл обратно через тот же транспорт. Автоматической очистки архива
нет. Нужен обновлённый helper; v0.33.0 этих методов ещё не поддерживает.
Снимки не заменяют резервное копирование домена и проверку восстановления.

### Холодная копия DC без Samba CLI

`domain.backup.start/status` используют Python-библиотеки Samba напрямую;
`samdb`, `dbchecker` и `ntacls` вызываются как API. Обработчики команд не вызываются.
На выбранном **RWDC** включите `helper.domain_backup_enabled: true`.
Нужны systemd, Python-модули Samba и каталог `backup_root` вне каталогов Samba.
Администратор заранее останавливает Samba в окне обслуживания; helper службы
не останавливает. Рабочий LDAP sambaadm должен оставаться доступен на другом RWDC.
Запрос сверяет GUID домена, имя DC и исходный план. Работающий Samba или RODC
блокирует создание копии.

Длительная операция выполняется отдельным systemd-заданием с PrivateNetwork,
UMask 0077 и лимитом 15 минут. SSH и HTTPS только запускают задание и читают статус.
Сохраните UUID до отправки: повтор того же запроса не создаёт вторую копию,
другой план с тем же UUID отклоняется. После разрыва соединения сначала прочитайте
статус. Ошибка определения состояния показывается как unknown; остановленный
незавершённый процесс — interrupted. Удаления архивов по таймеру нет.

Формат **sambaadm-cold-dc-v1** — холодная копия того же DC: базы, конфигурация,
SYSVOL, владельцы, режимы, xattrs и NT ACL SYSVOL. Это собственный формат, не
архив `samba-tool domain backup`. Содержит секреты домена. Каталоги 0700, файлы
0600; архив остаётся на helper, в браузер возвращаются только метаданные и SHA-256.
Лимиты: 10 ГиБ данных, 100 000 путей; неподдерживаемые типы файлов и изменения
источника во время чтения отклоняются. Объём временного хранения контролирует
администратор. Проверки выполнены на Samba 4.17 с TDB; другие версии и MDB требуют
отдельной приёмки. Это не резервная копия всего леса, ОС и внешних ресурсов.

Проверка восстановления реализована для **изолированного стенда**: только новый
каталог, без активных сетевых интерфейсов кроме loopback, с проверкой SHA-256,
файлов и ACL, отдельной конфигурацией путей и native dbcheck. Идентичность DC
сохраняется, поэтому копию нельзя запускать рядом с исходным DC в рабочей сети.
Для новой копии с планом worker автоматически выполняет восстановление именно
этого архива в `domain-backups/<UUID>/rehearsal`, проверяет базу и SYSVOL ACL,
сверяет объекты плана, фиксирует пробную очистку и проверяет возврат объектов после второго
восстановления исходного архива. Отдельный `restore.json` связывает успешный результат с UUID,
SHA-256 и ревизией плана; только он разрешает `restoreVerified=true`.
Это офлайн-проверка базы и файлов; запуск служб и клиентский вход в рабочей
копии автоматически не проверяются. Хранение архива и двух развёрнутых копий (репетиции и повторного восстановления)
требует дополнительного места; удаления по таймеру нет.

`topology.cleanup.reserve` повторно хеширует архив и создаёт одноразовую запись
`apply.json`. `topology.cleanup.event` сохраняет последовательные приватные
`apply-event-N.json` с fsync. Все эти операции выполняются через helper, LDAP/DRS
выполняет sambaadm. Статус копии возвращает `applyReserved` и `applyEvents`.
После потери ответа нельзя повторно применять ту же копию. Журнал с последним
`deleting` означает неопределённый результат: сначала обследуйте обе реплики.
Автоматического восстановления рабочего DC или отката реплицированного удаления
нет; восстановленную копию нельзя подключать к рабочей сети.


### Расширенная очистка выведенного DC

В полном аудите выберите сервер выведенного DC. Кандидат должен иметь отключённую
учётную запись DC либо подтверждённо отсутствующую учётную запись/ссылку на неё.
Само отсутствие сетевого ответа и возраст объекта не считаются доказательством
вывода. Отдельное подтверждение окончательного вывода (`confirmDecommissioned`)
обязательно; повторное подключение старого DC после очистки недопустимо.

Предпросмотр перечисляет все операции: NTDS Settings и связанные подключения,
RID Set, разрешённые локальные DFSR LocalSettings/Subscriber/Subscription,
глобальный DFSR Member и его подключения, ссылки размещения разделов, а также
конкретные значения DNS-записей. Новые или неизвестные дочерние объекты блокируют
выполнение. Рекурсивное удаление произвольного поддерева не применяется.

Для DNS различаются удаление выбранных значений и удаление LDAP-объекта. В общих
SRV/NS/A-узлах сохраняются записи остальных контроллеров. Удаляются A/AAAA имени
DC, его адреса в доменных DNS-корнях (при однозначной принадлежности), ссылки
SRV/CNAME/PTR/NS/MX на это имя. Последняя NS, SOA с этим DC как primary и адрес,
используемый другим именем, блокируют план: сначала исправьте DNS-конфигурацию.
Поддерживается AD-integrated DNS в доменном разделе, DomainDnsZones и
ForestDnsZones; внешние DNS-провайдеры/перенос зоны через AXFR не обслуживаются.
Клиентские DNS-кэши очищаются согласно TTL, а не этим планом.

Холодная копия создаётся на **оставшемся** RWDC. Helper восстанавливает именно
этот архив в изоляции, применяет весь план с фиксацией каждого шага, проверяет базу и сохранность
остальных значений, затем заново восстанавливает архив в другой изолированный
каталог и сверяет возврат исходных GUID/атрибутов. Это проверяет реальное
восстановление после зафиксированной очистки, включая отложенное обслуживание
связанных атрибутов Samba. Для двух развёрнутых копий требуется дополнительное место.
Копия и квитанция связаны с ревизией плана и SHA-256. До применения нужно снова
запустить DC копирования и дождаться исправной репликации.

Перед записью повторяются сверка плана на всех оставшихся RWDC, проверки FSMO,
зависимостей и DRS. Ответ LDAP от удаляемого DC блокирует очистку; текущий
LDAP-контроллер удалить нельзя. Ошибки DRS к подтверждённо удаляемому DSA могут
быть исключены, ошибки между оставшимися DC — нет. Локальные счётчики RID не
сравниваются между репликами; вычисляемые обратные ссылки не изменяются вручную.
Перед удалением NTDS снова проверяются ревизии сервера/учётной записи и отсутствие
LDAP-ответа. Чужие одновременные изменения топологии должны быть приостановлены.

Каждая запись защищена LDAP assertion и журналируется до/после выполнения.
После очистки синхронизируются Configuration, доменный раздел, DomainDnsZones и
ForestDnsZones. На каждом оставшемся RWDC проверяются удалённые объекты,
изменённые ссылки и сохранность остальных значений DNS. При конфликте, ошибке
или потере ответа возможен частичный результат: сначала читайте журнал по ID
копии. Слепой повтор и автоматический откат в рабочий домен не выполняются.

Текущие ограничения: один домен, минимум два оставшихся RWDC, максимум 16
зарегистрированных контроллеров; RODC-реплики и удаление NTDS RODC требуют
отдельного сценария. До 50 выбранных находок, до 150 объектов после расширения,
до 10 000 DNS-узлов при обследовании, копия моложе 24 часов. Требуется обновить
и sambaadm, и helper. Проверенная платформа — Samba 4.17/TDB; ALT/MDB и Windows DC
требуют отдельной приёмки. Проверка каждой рабочей копии выполняется офлайн,
без автоматического запуска восстановленного DC в рабочей сети.

Проверка после репетиции учитывает маркеры удаления связанных атрибутов Samba 4.17:
они сохраняются для репликации. Допустимы только неактивные ссылки размещения
разделов с точными исходным DN, атрибутом и GUID удалённого объекта из плана.
Активная ссылка, посторонний GUID или любая другая ошибка `dbcheck` блокируют
результат; автоматическое исправление базы и принудительное удаление маркеров
не выполняются. До репетиции и после второго восстановления проверка выполняется
без этих исключений. Старые квитанции восстановления не разрешают применение:
нужна новая копия с квитанцией `offline-dbcheck-cleanup-second-restore`.
