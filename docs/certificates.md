# Сертификаты и подключения

Администратор открывает **Настройки → Управлять сертификатами**. Раздел доступен
только роли admin; изменения защищены CSRF и записываются в аудит.

## LDAP контроллера

Кнопка проверки получает сертификат с LDAPS-порта настроенного контроллера без
отправки LDAP-пароля. Страница показывает владельца, издателя, DNS SAN, окончание
срока и результат проверки цепочки и имени. Даже недействительный сертификат
можно осмотреть; это не добавляет его в доверенные и не отключает проверку TLS.
При временном ldap:// проверяется порт 636 того же хоста, а не порт 389.

Для локального выпуска укажите FQDN и загрузите/вставьте CSR либо явно выберите
создание нового ключа. ZIP содержит ca.pem, cert.pem, smb.conf.fragment и порядок
установки. При создании ключа добавляется key.pem; этот ключ не сохраняется на
сервере приложения. Сертификат получает указанный DNS SAN и выбранный срок: 1, 3, 5 или 10 лет (по умолчанию 10). Он не может действовать дольше подписавшего УЦ. Новый локальный УЦ создаётся на 20 лет; существующий при одиночном выпуске не заменяется.
Повторный выпуск использует тот же локальный УЦ, поэтому обновлять доверие при
каждом продлении не требуется. Приватный ключ УЦ не входит в скачиваемые файлы.

Установка файлов на контроллер, изменение smb.conf и перезапуск Samba выполняются
на самом контроллере. Веб-форма не меняет действующие TLS-файлы удалённого сервера.
При работе с существующим ключом путь tls keyfile должен указывать именно на него.

В блоке доверия загрузите CA в PEM или нажмите «Доверять локальному УЦ sambaadm».
Сохраняются только действующие CA с правом подписи сертификатов; закрытые ключи и
серверные сертификаты не принимаются. Новые соединения службы и пользователей
используют обновлённое доверие без перезапуска. Текущее соединение службы закрывается
для повторного подключения. «Вернуть доверие из конфигурации» удаляет загруженное
переопределение и снова использует ldap.ca_cert и системное хранилище.

Состояние хранится в server.certificate_dir (по умолчанию
/var/lib/sambaadm/certificates): каталог 0700, файлы 0600. Сохраняйте каталог в
закрытой резервной копии вместе с enrollment. Загруженный ldap-ca.pem имеет
приоритет над ldap.ca_cert; сам YAML не переписывается. Потеря authority.json
означает потерю ключа локального УЦ. Сертификат УЦ можно скачать отдельно из меню.

## Сертификаты на всех контроллерах из интерфейса

Для DC на ALT Linux с systemd откройте **Настройки → Управлять сертификатами →
Развернуть сертификаты на всех контроллерах**. Обновите приложение и
`sambaadm-helper` на всех DC до сборки с поддержкой `certificate.prepare`.
Helper должен быть зарегистрирован на каждом DC, включая RODC; обычная установка
RPM регистрации не заменяет. Панель обнаруживает список DC в каталоге.

1. Выберите срок, например **10 лет**, и нажмите **Подготовить план для всех DC**.
   Если срока УЦ недостаточно, включённая опция продления выпустит новый публичный
   сертификат УЦ на 20 лет с тем же ключом. Прежний `authority.json` сохраняется
   в приватной резервной копии. Ключ УЦ не отправляется на контроллеры.
2. Проверьте все имена, результаты предварительной проверки и фактические даты
   окончания сертификатов. На DC создаются индивидуальные ключи и CSR; закрытые
   ключи DC остаются на соответствующих узлах. Подготовка не заменяет действующие
   TLS-файлы. Если helper отсутствует или устарел, план не допускается к применению.
3. Подтвердите перезапуски Samba и нажмите **Применить план на всех DC**.
   Сначала публичный сертификат УЦ добавляется в доверие приложения и **каждого** DC
   с сохранением прежних УЦ. На ALT обновляется системное хранилище через
   `update-ca-trust`, в Samba — `tls cafile`. Только после успешного завершения
   этой стадии на всех DC начинается установка серверных сертификатов.
4. Сертификаты устанавливаются по одному контроллеру. После перезапуска проверяются
   цепочка, DNS SAN, срок и соответствие выданному сертификату: локально helper и
   по сети с сервера sambaadm. Успех отмечается только после проверки всех DC.

[Samba использует отдельные параметры](https://www.samba.org/samba/docs/current/man-html/smb.conf.5.html)
`tls cafile`, `tls certfile` и `tls keyfile`. Поэтому одного копирования CA
недостаточно: каждому DC нужен собственный сертификат с его FQDN в SAN и
соответствующий закрытый ключ. Общим для узлов является публичный сертификат УЦ.

Доверие и сертификат активируются отдельными последовательными перезапусками
Samba. Файлы размещаются в `/etc/samba/tls-sambaadm/ID-ПЛАНА/`, а исходный
`smb.conf`, ключ и журнал — в `helper.state_dir/ldap-certificates/ID-ПЛАНА/`.
Автоматическая настройка не поддерживает `smb.conf` с внешними include или
реестровым backend: предварительная проверка остановит такой план.

При ошибке дальнейшие узлы не изменяются. Если установка нового сертификата
на узле не прошла проверку, helper пытается вернуть конфигурацию перед этой
операцией и перезапустить Samba. Результат восстановления виден в ошибке.
В панели можно отдельно подтвердить **Откатить ИМЯ-DC**, чтобы вернуть исходные
TLS-настройки этого контроллера. Дополнительное доверие к УЦ остаётся: его удаление
могло бы нарушить работу уже обновлённых узлов. Конфигурация, изменённая извне
после подготовки, не перезаписывается.

Планы и результаты сохраняются в `server.certificate_dir/rollouts`.
После перезапуска приложения прерванная работа не повторяется автоматически.
Кнопка **Сверить состояние и продолжить** сначала читает журналы всех helper;
неопределённый результат операции требует проверки или отдельного отката узла.
План до первого применения действует час. В закрытые резервные копии включайте
каталоги состояния приложения и helper: они содержат ключи.

Рабочим станциям и другим приложениям, которые проверяют LDAPS этих DC,
также нужно доверие к этому УЦ. Развёртывание на контроллеры само по себе
не изменяет хранилища доверия клиентов.

## Helper

Ссылка «Подключить helper или продлить сертификат» открывает форму регистрации.
Вариант по умолчанию создаёт ключ и сертификат в меню; ZIP включает tls.key,
config.yaml, tls.crt и management.pub. Приватный ключ выдаётся только в архиве.
Для ключа, уже созданного на узле, выберите подпись CSR: в архиве приватного ключа
не будет. CSR можно вставить или загрузить из PEM-файла. Передавайте архивы с
ключами по защищённому подключению и устанавливайте файлы с правами root:root 0600.

Повторная регистрация имени перевыпускает сертификат. Установите комплект на узле,
перезапустите helper и загрузите обновлённый реестр перезапуском sambaadm.
Изменения локального helper YAML при повторном выпуске сохраните отдельно.

## Локальные метрики

Дашборд получает CPU, RAM и использование системного диска непосредственно с
сервера приложения. Регистрация helper и helpers.host_node на эти метрики не
влияют. На первой точке CPU может быть пустым: процент вычисляется по двум
замерам с интервалом 5 секунд. История собирается при открытом дашборде.

## Совместимость с LDAP-сертификатами без SAN (v0.39.0)

В расширенных параметрах окна входа можно включить точное совпадение CN для
конкретной сессии. По умолчанию режим выключен. В настройках сертификатов
администратор может сохранить умолчание для новых входов и CLI; аналогичный
параметр YAML — ldap.allow_legacy_cn. Существующая сессия сохраняет свой выбор.

Совместимость применяется только к сертификату без расширения SAN и только к
точному DNS-имени CN без wildcard. IP в CN, другой CN, несовпадающий либо только
URI/email SAN, неизвестный CA, истёкший срок и неправильное назначение отклоняются.
Цепочки с ограничениями имён требуют SAN: ограничения CA не обходятся.
Общие LDAP-соединения строгого профиля и профиля совместимости разделены, поэтому
одна сессия не ослабляет другую. Проверка HTTPS-сертификатов helper не меняется.

Настройка по умолчанию сохраняется в server.certificate_dir/ldap-legacy-cn.json.
Флаг окна входа не сохраняется в YAML и относится только к вошедшему пользователю.
Для проверки через меню сертификатов применяется TLS-профиль текущей сессии.

## Временный тест без проверки LDAP-сертификата (v0.39.1)

В окне входа → «Расширенные параметры» доступна отдельная галочка
«Не проверять LDAP-сертификат (только для теста)». По умолчанию она выключена.
При включении LDAPS остаётся зашифрованным, но CA, SAN/CN, срок действия и
назначение сертификата не проверяются. Это допускает подмену сервера и перехват
учётных данных. Для рабочего окружения добавьте доверенный CA и используйте
проверку сертификата.

Выбор относится только к текущей сессии и её LDAP-операциям, включая фоновые
задания и другие DC. Обычные сессии используют отдельные проверяемые соединения.
Глобальная конфигурация не переписывается, автоматического отключения при ошибке нет.
В верхней панели показывается состояние отключённой проверки. Выход и новый вход
без галочки возвращают обычную проверку. HTTPS-сертификаты helper проверяются
по-прежнему. Инспектор сертификата в меню продолжает показывать реальные ошибки
цепочки/имени, даже если для LDAP-соединения выбран временный обход.
