# Сертификаты и подключения

Администратор открывает **Настройки → Управлять сертификатами**. Раздел доступен
только роли admin; изменения защищены CSRF и записываются в аудит.

## LDAP контроллера

Кнопка проверки получает сертификат с LDAPS-порта настроенного контроллера без
отправки LDAP-пароля. Страница показывает владельца, издателя, DNS SAN, окончание
срока и результат проверки цепочки и имени. Даже недействительный сертификат
можно осмотреть; это не добавляет его в доверенные и не отключает проверку TLS.
При временном ldap:// проверяется порт 636 того же хоста, а не порт 389.

Для локального выпуска укажите FQDN и загрузите/вставьте CSR либо явно выберите
создание нового ключа. ZIP содержит ca.pem, cert.pem, smb.conf.fragment и порядок
установки. При создании ключа добавляется key.pem; этот ключ не сохраняется на
сервере приложения. Сертификат получает указанный DNS SAN и срок не более года.
Повторный выпуск использует тот же локальный УЦ, поэтому обновлять доверие при
каждом продлении не требуется. Приватный ключ УЦ не входит в скачиваемые файлы.

Установка файлов на контроллер, изменение smb.conf и перезапуск Samba выполняются
на самом контроллере. Веб-форма не меняет действующие TLS-файлы удалённого сервера.
При работе с существующим ключом путь tls keyfile должен указывать именно на него.

В блоке доверия загрузите CA в PEM или нажмите «Доверять локальному УЦ sambaadm».
Сохраняются только действующие CA с правом подписи сертификатов; закрытые ключи и
серверные сертификаты не принимаются. Новые соединения службы и пользователей
используют обновлённое доверие без перезапуска. Текущее соединение службы закрывается
для повторного подключения. «Вернуть доверие из конфигурации» удаляет загруженное
переопределение и снова использует ldap.ca_cert и системное хранилище.

Состояние хранится в server.certificate_dir (по умолчанию
/var/lib/sambaadm/certificates): каталог 0700, файлы 0600. Сохраняйте каталог в
закрытой резервной копии вместе с enrollment. Загруженный ldap-ca.pem имеет
приоритет над ldap.ca_cert; сам YAML не переписывается. Потеря authority.json
означает потерю ключа локального УЦ. Сертификат УЦ можно скачать отдельно из меню.

## Helper

Ссылка «Подключить helper или продлить сертификат» открывает форму регистрации.
Вариант по умолчанию создаёт ключ и сертификат в меню; ZIP включает tls.key,
config.yaml, tls.crt и management.pub. Приватный ключ выдаётся только в архиве.
Для ключа, уже созданного на узле, выберите подпись CSR: в архиве приватного ключа
не будет. CSR можно вставить или загрузить из PEM-файла. Передавайте архивы с
ключами по защищённому подключению и устанавливайте файлы с правами root:root 0600.

Повторная регистрация имени перевыпускает сертификат. Установите комплект на узле,
перезапустите helper и загрузите обновлённый реестр перезапуском sambaadm.
Изменения локального helper YAML при повторном выпуске сохраните отдельно.

## Локальные метрики

Дашборд получает CPU, RAM и использование системного диска непосредственно с
сервера приложения. Регистрация helper и helpers.host_node на эти метрики не
влияют. На первой точке CPU может быть пустым: процент вычисляется по двум
замерам с интервалом 5 секунд. История собирается при открытом дашборде.
