# Нативное подключение к домену с macOS — v0.20.0

Приложение использует LDAP/LDAPS, MS-DNSP, MS-DRSR, LSA/Netlogon RPC и SMB. В рабочем бинарнике нет запуска `samba-tool`, Python Samba, SSH или rsync для доменных операций. Сам контроллер домена по-прежнему должен предоставлять эти протоколы: Samba AD или совместимый сервер AD. Для транспортов используются Go-библиотеки go-ldap, go-msrpc и go-smb2.

## Тестовый домен на Mac

Нужны работающий Docker и Go. Из корня репозитория:

```sh
./testdata/samba/start-mac-lab.sh
```

Открыть http://127.0.0.1:8081. Логин `Administrator@sambaadm.test`, пароль `Lab-Only-Adm1n-Pass!`. Это общеизвестные реквизиты только изолированного учебного стенда; не используйте их в рабочем домене.

Редактор включён в конфигурации стенда. На новом домене сначала разместите шаблон ALT в Central Store, как описано ниже.

Скрипт запускает контроллер SAMBAADM.TEST, копирует его сертификат в `bin/lab/ca.pem`, создаёт `bin/lab/config.yaml`, собирает и запускает нативный бинарник Mac с отладкой. Файлы `bin/` не публикуются в Git. Docker-тома `mac-domain` и `mac-config` сохраняют домен между перезапусками. Повторный запуск обновляет доверенный сертификат приложения. Системное хранилище сертификатов macOS не изменяется.

Порты доступны только через loopback: LDAP 1389, LDAPS 1636, SMB 1445, RPC mapper 135 и RPC 49152–49162. Не публикуйте их на внешних интерфейсах. Остановить веб-сервер — Ctrl+C; остановить контроллер без удаления домена:

```sh
docker compose -p sambaadm-lab -f testdata/docker-compose.yml -f testdata/docker-compose.mac.yml stop
```

## Подключение к существующему домену

Настройте `ldap.uri`, `ldap.base_dn`, служебную учётную запись и группы ролей по `configs/config.example.yaml`. Пароль задайте через переменную, указанную в `ldap.bind.password_env`. Для частного центра сертификации используйте `ldap.ca_cert` — проверка сертификатов и имени сервера остаётся включённой. RPC использует ту же служебную запись, NTLMv2 и шифрование RPC; SMB требует подписи. Доменные пароли пользователей проверяются на отдельных LDAP-соединениях.

С Mac должны разрешаться DNS-имена всех DC и быть доступны LDAPS 636, SMB 445, RPC 135 и динамический RPC-диапазон контроллеров. На рабочем домене не используйте лабораторные переадресованные порты. Проверка соединения до запуска HTTP:

```sh
./sambaadm --config config.yaml serve --check
./sambaadm --config config.yaml serve --debug
```

## Операции и изменения форматов

- Пользователи, группы, компьютеры, OU, сайты и соединения репликации — LDAP.
- DNS: чтение, создание/удаление зон, добавление/изменение/удаление записей — RPC. Для SRV вводите `target port priority weight`, для MX — `target preference`, TXT — строки в кавычках; остальные типы используют обычное текстовое значение DNS.
- GPO: каталог и привязки — LDAP; файлы, ACL, создание, удаление, резервные копии и распространение SYSVOL — SMB. Перед удалением отвяжите GPO от всех OU, доменов и сайтов.
- Резервная копия нового формата находится в `policy/{GUID}/sambaadm-backup.json`; содержит файлы, права и метаданные. Восстановление создаёт новую непривязанную GPO в том же домене. Старые каталоги Samba с `.SAMBABACKUP` не являются этим форматом. Не передавайте копии посторонним: политики могут содержать чувствительные данные.
- Распространение `both` отдельно выполняет DRS и перенос файлов SMB. `drs` не переносит SYSVOL. Режим `smb` переносит файлы; старое имя `rsync` распознаётся как SMB. Копирование готовится во временном каталоге перед заменой. Используйте один контроллер как источник редактирования; ошибка шага останавливает доставку и видна в журнале задания.
- Статус репликации показывает входящих соседей DRS, результат и время синхронизации. Отсутствие партнёров не считается подтверждением исправной репликации. Зарегистрированные DC перечисляются отдельно.
- Доверие создаётся на локальной стороне: укажите DNS-имя, NetBIOS-имя, SID второго домена и общий пароль доверия. На второй стороне требуется согласованная настройка. Проверка использует Netlogon; создание объекта само по себе не подтверждает рабочее двустороннее доверие.
- FSMO и функциональные уровни управляются напрямую по LDAP; захват ролей остаётся аварийной операцией. Для переноса DNS FSMO требуется LDAPS к текущему владельцу с доверенным сертификатом.

## Границы проверки

Тестовый стенд использует Samba 4.17.12, а не ALT СП. Совместимость с конкретной ALT СП 10.2.2 требует проверки на ней. Linux-бинарники собираются с `CGO_ENABLED=0`, без зависимости от GLIBC_2.34.

Редактор ALT GPO работает удалённо по SMB и LDAP, включая чтение шаблона из Central Store. Включите `gpo.editor_enabled: true`, оставьте `gpo.admx_path: ""` и разместите `BaseALT*.admx` с языковыми ADML в `SYSVOL/<domain>/Policies/PolicyDefinitions/`. Локальный SYSVOL не требуется. Подробности и восстановление после сбоя — в [инструкции редактора](web.md#редактор-административных-политик-alt). Локальное администрирование smb.conf, POSIX ACL и CUPS относится к машине сервера приложения: оно не превращается в удалённое администрирование Linux при запуске на Mac. Для этих локальных функций сохраняются соответствующие системные средства ОС.

`testdata/` разворачивает тестовый контроллер средствами Samba, а некоторые интеграционные проверки сравнивают результат с её диагностическими утилитами. Они не входят в зависимости рабочего бинарника.
