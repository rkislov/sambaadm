# Аудит действий и передача CEF в syslog

**Аудит** показывает администратору последние 200 событий в обратном порядке. Время отображается в UTC. Запросы всех авторизованных ролей `admin`, `helpdesk` и `readonly` записываются как `web.request`. Каждая запись содержит имя пользователя, роль, время, HTTP-метод, шаблон маршрута, код ответа, длительность и адрес сетевого узла, который установил соединение с панелью. При проксировании адрес относится к прокси. Для связи с клиентским адресом проверяйте журнал доверенного прокси по времени запроса.

Журнал включает чтение, попытки изменения, отказы в доступе и ошибки CSRF. Вход с паролем, вход Kerberos и выход имеют отдельные события. Возврат HTTP 2xx или 3xx фиксирует успешный ответ панели. Фактический итог работы DHCP, печати, LDAP, SYSVOL или длительного задания проверяйте по соответствующему событию операции, журналу helper или карточке задания. События запросов и операций могут относиться к одному действию. Имя объекта из параметра запроса, строка запроса и тело запроса исключены из `web.request`.

## Включение на ALT p10 и p11

Оставьте `audit.file` настроенным и добавьте блок `syslog` к существующему разделу `audit` файла `/etc/sambaadm/config.yaml`. После изменения перезапустите `sambaadm`. Для собственного журнала операций helper используйте такую же настройку в `/etc/sambaadm-helper/config.yaml` и перезапустите службу HTTPS-helper. При подключении helper по SSH конфигурация читается при следующем вызове.

```yaml
audit:
  file: /var/log/sambaadm/audit.log
  syslog:
    enabled: true
    network: unixgram
    address: /dev/log
```

Локальный сокет `/dev/log` принимает сообщения с тегом `sambaadm` и facility `local0`. Если на узле используется централизованный rsyslog или syslog-ng, настройте пересылку этого тега и facility на приёмник SIEM. По умолчанию пересылка выключена. Значения можно задавать также переменными `SAMBAADM_AUDIT_SYSLOG_ENABLED`, `SAMBAADM_AUDIT_SYSLOG_NETWORK` и `SAMBAADM_AUDIT_SYSLOG_ADDRESS`.

Для прямой отправки задайте `network: udp`, `tcp` или `tls` и `address: имя-сервера:порт`. TCP и TLS используют обрамление с длиной в октетах. В режиме TLS сертификат проверяется по системному хранилищу доверия и тому имени, которое указано в адресе. Настройте корневой сертификат CA средствами ОС до перезапуска. UDP и TCP без TLS передают данные открытым текстом.

Для проверки войдите под тестовой учётной записью своей роли, откройте безопасный раздел и выйдите. Сравните строки `login`, `web.request` и `logout` в JSON с CEF у приёмника. Для локального journald используйте команду:

```bash
journalctl -t sambaadm --since '5 minutes ago' --no-pager -o cat | grep 'CEF:0|'
```

## Поля на стороне SIEM

- **Заголовок** содержит продукт и версию sambaadm, имя операции и важность. Успех получает 1, отказ 5, HTTP 5xx — 7.
- **`rt`, `suser`, `act`, `outcome`** содержат время в миллисекундах с начала эпохи Unix, учётную запись, действие и результат.
- **`src`, `c6a1`** содержат IPv4 или IPv6 сетевого узла. **`cs1`** содержит роль при наличии.
- **`requestMethod`, `request`, `cn1`, `cn2`** содержат HTTP-метод, шаблон маршрута, код ответа и длительность в миллисекундах.

CEF передаёт ограниченный набор полей. Тексты внутренних ошибок, расширенные детали и имена объектов из событий операций остаются в локальном журнале. Храните журнал и архивы с доступом администраторов и учитывайте срок хранения персональных данных. Настройте ротацию с сохранением открытого файла или с перезапуском приложения после замены файла.

Передача идёт через очередь в памяти. При сбое приёмника, остановке процесса или переполнении очереди часть CEF-сообщений может отсутствовать. Для сверки используйте локальный JSON. Причину сбоя ищите в журнале службы по сообщениям `audit syslog delivery failed`, `audit syslog queue full` и `audit syslog flush timed out`.
