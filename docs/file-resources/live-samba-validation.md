# Живая проверка шаблонов прав и наследования

Проверено 26 ноября 2026 года на Samba 4.17.12-Debian, Debian Bookworm, Linux arm64 в изолированном Docker-стенде. Домен `SAMBAADM.TEST`, два действующих DC и helper, реальный LDAP/NSS и подписанный SMB. Результат: обе выбранные интеграционные проверки завершились `PASS`.

[Вывод успешного прогона](live-samba-validation.txt) · [Исходник интеграционного теста](../../internal/service/share_permission_map_integration_test.go).

## Что проверено

Созданы три доменные группы безопасности, два пользователя и отдельный общий ресурс с пятью исходными каталогами:

```text
.
├── Team
│   ├── Reports
│   └── Archive
└── Other
```

Наложены три шаблона: чтение/проход от корня, совместная работа на поддереве `Team`, более позднее правило только чтения для `Team/Archive`. Вторая группа остаётся только для чтения. Третья группа имеет исходное `rwx`, ограниченное ACL-маской до `r-x`.

Проверки выполнялись настоящими сервисами и системными утилитами:

- Группы созданы в AD и разрешены через NSS на файловом сервере. Использованы серверные GID, а не идентификаторы машины управления.
- Снимок и план охватили все пять каталогов. При добавлении каталога после предпросмотра применение отклонило устаревшую карту до записи прав.
- Применение через HTTPS-helper завершилось успешно для каждого каталога. На `Team` действует `rwx`, а на `Team/Archive`, корне и `Other` — `r-x` для проверяемой RW-группы.
- Эффективные права третьей группы остались `r-x` после расширения маски. Скрытый ранее `w` не вернулся.
- В каждой ветке созданы новая папка и файл внутри неё. Проверены ACL доступа и ACL по умолчанию, включая наследование через два уровня. При создании обычного Linux-файла с режимом `0666` эффективный `x` отсутствует.
- ACL и режим файла, существовавшего до применения, остались прежними.
- Настоящий RW-пользователь создал папку и файл по SMB. RO-пользователь прочитал файл, но получил отказ при создании и перезаписи. RW-пользователь также получил отказ записи в `Archive` и `Other`, сохранив чтение архива.
- В приватном журнале `0600` проверены исходные ACL, план и итоговые статусы всех пяти каталогов.

После тестов тестовые пользователи, группы и ресурс удалены; контейнеры и сеть стенда остановлены и удалены штатным сценарием.

## Особенности Samba, выявленные проверкой

**Наследование POSIX ACL и параметр `inherit acls` — разные механизмы.** С `inherit acls=no`, `create mask=0666` и `directory mask=0777` новые SMB-файлы получили эффективные разрешения `rw-`/`r--` для проверяемых групп. ACL по умолчанию при этом продолжили наследоваться.

При переключении того же тестового ресурса в `inherit acls=yes` новый SMB-файл получил режим `0770`: RW-группа унаследовала `rwx`, RO-группа — `r-x`. Это наблюдение подтверждено `getfacl`, а не вычислено только по шаблону. Семантика переключателя описана в [официальной документации Samba](https://www.samba.org/samba/docs/current/man-html/smb.conf.5.html#INHERITACLS).

**Ресурс проверялся с POSIX ACL.** Для него явно заданы `vfs objects=dfs_samba4` и `acl_xattr:ignore system acls=no`. Глобальная тестовая конфигурация SYSVOL с отдельным Windows NT ACL/xattr-хранилищем сохранена. Успех этого прогона не подтверждает управление Windows DACL через POSIX-редактор и не заменяет проверку на ALT или другой версии Samba.

## Право x на каталогах и Caja

Вывод об отсутствии `x` в предыдущем разделе относится к **обычным файлам**,
создаваемым с файловой маской без выполнения. На каталогах право `x` означает
проход и должно сохраняться, в том числе для доступа только на чтение (`r-x`).
ACL-маска также не должна убирать это право.

[Отдельная проверка в настоящей Caja на ALT p11](caja-alt-p11/README.md) подтвердила
отказ открытия без эффективного `x` локально и по SMB и восстановление доступа
после возврата `x`. Профили шаблонов каталогов используют `r-x` и `rwx`.

## Исправление подготовки стенда

Ранее сценарий подготовки helper выполнял `umask 077`, затем создавал `/srv/samba` через `mkdir -p`. В результате родительский каталог получал `0700`: доменный пользователь не мог пройти к ресурсу даже с правильным ACL внутри него. Подготовка исправлена: `/srv/samba` создаётся с `0755`, приватное состояние helper — с `0700`. Также в образ добавлены NSS-модули winbind для разрешения настоящих доменных групп.

## Повторный запуск

Из корня репозитория, с запущенным Docker и установленным Go:

```sh
SAMBAADM_TWO_DC=1 SAMBAADM_HELPERS=1 \
SAMBAADM_IT_TEST_PATTERN='IntegrationSharePermissionTemplatesAndInheritance|IntegrationHostHelperFilesystemConfinement' \
testdata/samba/run-integration.sh
```

Тесты изменений разрешены только при явном включении интеграционного режима и проверке учебного Base DN. Используется отдельный временный Compose project; сценарий очищает его и при ошибке.
