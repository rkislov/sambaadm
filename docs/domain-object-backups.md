# Резервные копии доменных объектов

Администратору доступен раздел **Резервные копии** (`/backups`). Нажмите
«Создать резервную копию объектов», откройте сохранённый снимок и выберите
пользователя, АРМ или GPO. Кнопка проверки показывает возможность восстановления
и ограничения. Запись выполняется отдельным подтверждённым запросом.

## Состав и хранение

Логический снимок содержит профили пользователей и компьютеров, метаданные OU,
групп, состава групп и привязок GPO, а также содержимое всех GPO: настройки LDAP,
файлы SYSVOL и разрешения файлов/каталогов SYSVOL. Он не содержит паролей,
Kerberos-ключей, секретов компьютеров, полной базы AD, DNS-разделов, конфигурации
контроллера и LDAP ACL. Для аварийного восстановления контроллера используйте
отдельный полный Samba domain backup. Этот раздел не заменяет такой бэкап.

Снимок читается последовательно из LDAP и SMB, а не в общей транзакции. На время
копирования приостановите изменения объектов и политик. Ошибка чтения любого
объекта или SYSVOL отменяет публикацию копии. Ограничения: 50 000 объектов и
256 МиБ на снимок; дополнительные ограничения существующего GPO backup —
64 МиБ файлов и 10 000 записей на политику. LDAP-ответ с диапазонными атрибутами
(например, очень большая группа) отклоняется, чтобы не сохранить неполные данные.

`server.backup_dir` задаёт абсолютный путь на **сервере sambaadm**, по умолчанию
`/var/lib/sambaadm/backups`. Это не каталог на helper/DC. Каталог создаётся с
правами `0700`, файлы — `0600`; существующий каталог с доступом группы/остальных
отклоняется. Копия публикуется только после записи и fsync; UUID-файлы никогда
не перезаписываются. SHA-256 проверяет повреждение содержимого, но не является
цифровой подписью. Доступ к каталогу должен иметь только процесс sambaadm.

Автоматической очистки или расписания нет. Переносите копии на отдельный носитель
и контролируйте свободное место. «Скачать снимок JSON» выгружает тот же формат
с контрольной суммой. Для возвращения архивной копии остановите sambaadm или
дождитесь завершения операций, поместите доверенный файл `<UUID>.json` в
`server.backup_dir` с владельцем процесса sambaadm и правами `0600`, затем
откройте раздел. Загружать произвольные JSON через HTTP нельзя.

## Восстановление

Проверяются GUID домена, GUID объекта, занятость имени/DN и наличие исходного
родительского контейнера. Изменение удалённого объекта между предпросмотром и
записью требует повторного предпросмотра. LDAP assertion защищает undelete и
последующую запись профиля; отключение также проверяет исходный GUID.
Операции создания копии и восстановления журналируются в аудите.

**Пользователи и АРМ:** восстанавливается исходный tombstone с исходными SID и
GUID, затем разрешённые атрибуты профиля из снимка. Учётная запись отключается
отдельным запросом сразу после undelete; восстановление состоит из нескольких
LDAP-операций, поэтому до отключения есть промежуточное состояние. Если отключить
объект не удалось, операция возвращает явную ошибку с требованием немедленно
проверить состояние учётной записи. Пароли и членство в группах не записываются из копии;
проверьте фактические права, задайте пароль и только затем включайте пользователя.
Для АРМ может потребоваться восстановление доверия/повторный ввод в домен.
Восстановление учётных записей DC/RODC через эту функцию запрещено. Если tombstone
уже недоступен, создание новой учётной записи с другим SID автоматически не
выполняется. При частичной ошибке объект может уже быть восстановлен и отключён;
сообщение содержит это состояние. Проверьте его вручную перед дальнейшими действиями.

**GPO:** используется существующий механизм восстановления в **новую** GPO с новым
GUID. Восстанавливаются настройки и файлы/разрешения SYSVOL. GPO остаётся без
привязок: LDAP-делегирование, фильтрацию безопасности, WMI-фильтр и привязки нужно
проверить и настроить вручную. При ошибке новая GPO может остаться для диагностики;
не повторяйте восстановление вслепую. Оригинальные OU, группы и `gPLink`/`gPOptions`
доступны в `snapshot.objects[].attributes` скачанного JSON для справки.

Существующие объекты не перезаписываются. OU и группы в этой версии сохраняются
для справки, их выборочное восстановление не поддерживается. У служебной LDAP
учётной записи должны быть права чтения удалённых объектов, Reanimate Tombstone
и изменения восстанавливаемых профилей; SYSVOL читается и записывается через
существующий механизм учётных данных GPO/SMB.

## REST API

Все маршруты требуют роли `admin`; POST также требует `X-CSRF-Token`.

- `GET /api/v1/backups` — список метаданных копий.
- `POST /api/v1/backups` — создать снимок, ответ `201` с метаданными.
- `GET /api/v1/backups/{id}` — метаданные и инвентарь объектов без файлов SYSVOL.
- `GET /api/v1/backups/{id}?download=true` — скачать формат хранения с SHA-256.
- `GET /api/v1/backups/{id}/objects/{guid}/preview` — `canRestore`, причина,
  ограничения и `revision` для конкретного объекта.
- `POST /api/v1/backups/{id}/objects/{guid}/restore` —
  `{"revision":"значение из preview","confirm":true}`.

`guid` — hex сырых 16 байт LDAP `objectGUID`, как в инвентаре снимка, без
перестановки байтов в стандартное строковое представление UUID. Ответы содержат
`Cache-Control: no-store`. Ошибки операций возвращаются с кодом `400`, отказ
доступа — `401/403`; после ошибки восстановления прочитайте сообщение о частичном
результате и проверьте живой объект.

## Полный холодный бэкап контроллера

В том же разделе `/backups` доступен **Полный бэкап контроллера**, независимо от
планов очистки топологии. Это собственный формат `sambaadm-cold-dc-v1`: копия баз
AD (включая секреты), SYSVOL, конфигурации Samba, владельцев, режимов, xattrs и
NT ACL SYSVOL для того же DC. Это не образ ОС, не резервирование всего леса или
внешних файловых ресурсов и не формат `samba-tool domain backup restore`.

На выбранном RWDC нужен обновлённый helper с `helper.domain_backup_enabled: true`,
абсолютным `helper.backup_root` вне каталогов Samba, Linux/systemd и библиотеками
Python Samba. Каталог `backup_root` создайте заранее и предоставьте только root.
Другие версии/хранилища, кроме проверенного Samba 4.17 с TDB, требуют отдельной
приёмки. Внешние/registry include конфигурации и неподдерживаемые типы файлов
отклоняются. Поддерживаемые корни: private/state, SYSVOL и каталог smb.conf;
внешние данные и нестандартные зависимости сохраняйте отдельным планом.

Порядок работы:

1. Пока LDAP доступен, выберите RWDC с зарегистрированным helper и нажмите
   «Подготовить полный бэкап». Сервер проверяет DC и сохраняет GUID домена,
   FQDN, UUID и ревизию запроса в закрытом `server.backup_dir`. Подготовка
   действительна 24 часа; сама по себе она ещё не создаёт архив.
2. В согласованное окно обслуживания остановите службы Samba на выбранном DC.
   Оставьте helper и sambaadm работающими. Приложение службы не останавливает.
   Если это единственный DC, LDAP/аутентификация домена временно недоступны.
   Уже открытая сессия позволяет запустить задачу и проверить статус; после
   истечения сессии для нового входа понадобится снова работающий LDAP.
3. Подтвердите остановку и нажмите «Запустить полный бэкап». Helper дополнительно
   проверяет отсутствие процессов Samba, идентичность домена/DC и RODC-флаг.
   Запуск и статус подготовленной задачи не обращаются к LDAP. Повторный запуск
   того же UUID возвращает ту же задачу, а не создаёт вторую копию.
4. Нажимайте «Обновить статус». Нужны одновременно `status: backed_up` и
   `restoreVerified: true`. `queued`, `running`, `unknown`, `interrupted` и `failed`
   не подтверждают готовность. При ошибке прочитайте закрытый `worker.log` на
   helper; перед повторной попыткой проверьте предыдущий статус.
5. После завершения задачи запустите Samba вручную и проверьте работу домена.
   Скопируйте архив и `request.json`, `status.json`, `restore.json` из
   `helper.backup_root/domain-backups/<UUID>/` в защищённое отдельное хранилище.
   Архив содержит секреты и через браузер не передаётся.

Копирование и пробное восстановление выполняются в отдельном systemd-задании
с изолированной сетью, правами `0077` и лимитом 15 минут. Лимиты архива:
10 ГиБ данных и 100 000 путей; нужно место для архива и пробной восстановленной
копии. Источник должен оставаться остановленным до окончания задания.
Автоматического удаления архивов или перезапуска Samba нет.

После создания архив проверяется, восстанавливается в новый временный каталог,
проходит dbcheck и сверку SYSVOL ACL. Изолированная копия DC запускается только
на loopback: проверяются вход тестовым пользователем, отказ при неверном пароле,
чтение SYSVOL, получение Kerberos TGT, LDAP и CIFS без NTLM-fallback. Все тестовые
процессы завершаются, а неизменность исходного архива проверяется повторно.
Квитанция `live-dc-kerberos-ldap-sysvol-full-v1` относится только к полному бэкапу
и не разрешает применение очистки топологии.

Пробное восстановление не является восстановлением рабочего DC. Endpoint для
перезаписи действующей базы не добавлен. Для аварийного восстановления сначала
используйте изолированную среду с совместимой версией Samba и отдельным планом
возвращения DC в домен; не распаковывайте архив поверх работающего контроллера.

API (admin; POST требует CSRF):

- `POST /api/v1/backups/full/prepare`, `{"controller":"dc1.example.com"}` —
  подготовка, ответ `201` с `id` и `planRevision`.
- `GET /api/v1/backups/full` — сохранённые подготовки и история UUID.
- `POST /api/v1/backups/full/{id}/start`,
  `{"revision":"planRevision из подготовки","confirmStopped":true}` — `202`.
- `GET /api/v1/backups/full/{id}` — статус с helper без LDAP, включая
  `restoreVerified`, `sha256`, `bytes` и результат живой проверки.
